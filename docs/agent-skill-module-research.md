# LawVerify 智能体与技能模块调研

调研日期：2026-10-28

状态：产品调研与设计建议，尚未实施。

## 一、结论

建议在 App 最左侧功能栏新增「智能体」入口，内部使用「我的智能体」「我的技能」「模板」三个页签，不分别增加两个顶层入口。

优先借鉴 TRAE 的自然语言生成和技能表单、ChatGPT GPTs 的配置与试运行、Claude 的技能复用与启停。扣子的能力装配方式值得借鉴，Dify 的工作流画布不宜作为律师用户的默认入口。

普通用户应能通过“选模板或描述需求 → 检查配置 → 试运行 → 保存并使用”完成创建，不需要编写 Markdown、配置模型 API 或理解工具协议。

## 二、研究范围与证据边界

本次依据官方产品说明调研配置入口、字段、创建流程、调用方式和权限；未登录这些平台逐一实测，不将文档示意作为当前账号下的实际截图。

各平台能力、地区和套餐限制可能变化。下表中的产品事实来自官方文档，“借鉴建议”为针对 LawVerify 的设计判断。

| 平台 | 官方描述的主要方式 | 值得借鉴 | LawVerify 不宜直接照搬 |
| --- | --- | --- | --- |
| TRAE | Agent 支持智能生成和手动创建，配置提示词、内置工具和 MCP；通过 `@` 选择 Agent。Skill 支持 AI 创建、表单创建、导入 `SKILL.md`/ZIP 自动回填、市场安装和启停 | 一句话创建；导入后可编辑；技能名称、描述、规则的简洁表单 | 面向开发者的终端、路径和工具协议不应默认展示给律师 |
| ChatGPT GPTs | 对话式构建或直接配置；设置名称、说明、指令、知识资料和能力；提供 Preview、草稿、更新和版本恢复 | 创建与试运行衔接；资料与行为规则分开；草稿不直接影响已使用版本 | 自定义 GPT 不应直接等同于开放 Skill 标准；不必复制公共商店和大量配置项 |
| Claude Skills | 在 Customize > Skills 上传技能 ZIP 并启停；相关任务自动使用；技能可含规则、参考资料和脚本；提供个人、共享和组织技能机制 | Skill 是可复用的专业方法；按需加载；来源和启用状态清楚 | ZIP 上传不能成为普通用户唯一创建方式；不能默认执行第三方脚本 |
| Coze / 扣子 | Agent 支持 AI 创建与模板；开发页配置人设、扩展能力并实时预览调试；低代码 Agent 文档将插件、工作流和知识放在 Skills 区域；新的技能文档描述 `SKILL.md` 等模块化包 | 选能力而非写接口；创建后就能试用；按任务提供模板 | 三栏配置页易在笔记本上拥挤；其广义 Skills 区域与标准技能包须区别对待 |
| Dify | Agent 节点配置模型、策略、工具、指令、上下文及最大迭代次数，输出工具结果和运行日志 | 工具授权明确；执行次数限制；问题可追溯 | 工作流画布、变量语法、推理策略应归入专业能力，不作为默认配置步骤 |

## 三、先区分 Agent、Skill、工具和资料

- **Agent / 智能体**：负责某一类工作的助手，定义职责、回答要求、可用技能及权限。例如“劳动争议质证助手”。
- **Skill / 技能**：可重复使用的办事方法，定义适用场景、步骤、约束、输出格式和模板。例如“工资流水核对”。
- **工具**：真正执行检索、读取、计算、生成文档等操作的能力。写一段指令不代表获得对应工具。
- **资料**：供参考的知识和原文。案件证据属于案件上下文，不应复制到可共享的技能包中。

一个 Agent 可使用多个 Skill；一个 Skill 可复用于多个 Agent。第一版不要求支持 Agent 互相调用。

例如“劳动争议质证助手”可以使用“工资流水核对”“时间线整理”“质证意见硬模板”等技能，同时仅获准读取当前案件及所选知识库。

## 四、导航和页面布局

当前最左侧导航由 `app/src/IdeActivityBar.tsx` 定义，包含资源管理器、文书工作区、案件助手和知识库，可在同层级增加入口。

建议结构：

```text
最左侧功能栏 → 智能体

我的智能体 | 我的技能 | 模板
搜索                              新建 / 导入

左侧：当前页签的列表
右侧：选中项详情、配置或试运行
```

新增入口显示可识别名称，不能仅靠一个含义不明的小图标。选中后进入独立主页面，不在证据目录中塞入配置面板。

默认两栏，列表可收起；右侧配置表单采用上下堆叠。试运行可切换显示，在宽屏上再允许并排展开，避免在主流笔记本上默认出现三条窄列。

列表只显示名称、简短用途和启用状态；详情显示所选技能、资料及授权。复制、导出、删除等低频操作收进菜单。

不重复建设知识库上传界面，直接选择现有知识库或其中的资料。

## 五、创建 Agent

新建提供「描述需求」「使用模板」「手动配置」三种方式，默认描述需求。

示例输入：“帮我创建一个劳动争议质证助手，按我的模板逐项分析证据，重点检查工资、考勤和解除通知。”

系统生成草稿后显示以下配置：

| 配置项 | 用户操作 |
| --- | --- |
| 名称 | 自动生成，可修改 |
| 主要任务 | 用自然语言描述希望它做什么 |
| 工作要求 | 编辑回答规则、分析重点和输出要求；支持 AI 整理，但修改需用户确认 |
| 使用技能 | 搜索、勾选已有技能，查看简短用途 |
| 参考资料 | 选择已有知识库或资料，不默认绑定全部知识库 |
| 可用能力 | 以“读取当前案件证据”“检索法条”“生成文书”等业务文字授权 |

模型沿用用户现有可用配置，高级设置中再选择其他模型；创建每个 Agent 不应要求重复填写 API Key。

创建流程：生成草稿 → 调整 → 试运行 → 保存并使用。已有 Agent 修改时保留草稿，用户确认更新后才影响后续使用。

## 六、创建 Skill

提供「描述需求」「从办案方法或模板创建」「导入已有技能」三种入口。

默认表单：

| 配置项 | 用途 |
| --- | --- |
| 技能名称 | 用户可识别的中文名称 |
| 何时使用 | 明确适用任务和触发条件，不只填写关键词 |
| 如何处理 | 可编辑的分步办事方法 |
| 输出格式 | 文书结构、表格栏目或其他结果要求 |
| 模板与示例 | 可选上传，用于保持输出一致性 |

可让用户上传自己的质证模板，提炼出结构与写作规则后确认保存。不得将模板中的当事人信息、案号及证据事实默认固化为通用方法。

高级设置才展示原始 `SKILL.md`、依赖工具、调用方式和输入要求；普通表单与文件定义应一致，不能成为两套互不相通的配置。

支持导入 `SKILL.md` 和 ZIP：读取元数据 → 回填表单 → 展示所含文件、依赖及风险 → 用户确认保存。不能仅凭文件扩展名或同名说明文件认定可运行。

导出使用标准技能包结构，允许跨平台复用说明和资料；涉及平台工具、脚本环境或私有接口时展示兼容性问题，不承诺所有外部技能一键运行。

## 七、配置后如何真正使用

- 在案件助手顶部用明确的「选择智能体」控件切换，切换时展示当前生效的智能体名称。
- 可将智能体设为当前案件默认；未设置的案件沿用原案件助手。
- 技能仅在启用、已被当前 Agent 允许且与任务匹配时按需加载，不把所有技能全文永久拼入提示词。
- 在输入区提供「使用技能」选择器，兼容 `/` 快捷调用但不要求律师记命令。
- 自动使用技能时，用轻量状态提示显示当前技能名称，不在法律文书正文中插入执行过程。
- 输出默认进入预览，写入当前文书或覆盖已有内容必须由用户确认。

## 八、试运行与可靠性

试运行区允许输入问题、选择真实测试材料，流式显示结果，并提供停止按钮。不要生成虚构案件或演示证据冒充用户材料。

默认不修改正式案件、不覆盖文书、不进行外部发送。测试读取案件资料仍须用户授权，AI 调用若计费应提前明确提示并按现有云端账本处理。

用户可以查看本次实际使用的技能、资料和工具，以及失败原因；提供执行摘要，不要求展示模型内部思维链。

保留草稿和可恢复的配置版本。每次任务记录所用配置版本，避免后续修改使历史结果无法解释。

## 九、安全和商业化底线

- 个人配置默认仅本人可见；分享导出排除 API Key、会话凭证和案件事实。
- 案件权限按当前案件限制，切换 Agent 或导入技能不能获得其他案件数据。
- 第三方技能默认不启用。压缩包需校验路径穿越、解压大小、文件数量及依赖；内容检查不等同于安全保证。
- 脚本技能必须在受控执行环境运行；不允许直接借 Electron 权限执行用户电脑上的任意命令。
- 第一版可完整支持规则、模板和受控工具型技能；脚本或外部服务依赖未获支持时明确标记“不可运行”及缺失原因，不能静默降级为普通提示词。
- 自定义规则不能绕过真实性核验、法源要求、隐私和账户计费约束；规则不能保证法律结论正确。
- 设置执行次数、时间和调用预算上限，支持中止及失败处理；余额始终以云端权威账本为准。

## 十、建议实施顺序

1. 完成独立模块、Agent / Skill 结构及账号隔离，支持创建、编辑、复制、启停和草稿。
2. 接通自然语言生成、模板创建及技能文件导入导出，完成验证和兼容性提示。
3. 接通案件助手实际调用、技能按需加载和流式试运行，形成配置到使用的完整流程。
4. 完成案件权限、版本恢复、工具授权、成本限制与回归验证。
5. 在实际需求明确后扩展律所共享、外部工具接入、受控脚本及多 Agent 协作。

首轮验收重点：用户不写配置文件即可创建并使用智能体；同一技能可供多个智能体复用；禁用后不再调用；导入不能扩大权限；测试不覆盖正文；配置退出重进不丢失；13-15 寸笔记本布局可用。
