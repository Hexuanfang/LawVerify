# LawVerify 商用平台蓝图

## 1. 产品定位

LawVerify 不再按“演示型 AI 工具”建设，而按“律师证据质证作业平台”建设。

目标用户：

- 诉讼律师
- 律所团队负责人
- 办案辅助人员
- 平台运营与客服

目标结果：

- 让案件、证据、质证书、核验、归档进入统一平台
- 让每一句质证表述都可回溯到证据源
- 让个人试用、团队订阅、企业部署三种商业模式可落地

## 2. 商用版本的核心模块

### 2.1 账户与组织

- 账号注册、登录、找回密码
- 手机号 / 邮箱 / 企业 SSO
- 组织、团队、成员、角色
- 组织级资源隔离与权限控制

### 2.2 案件中心

- 案件创建、归档、标签、阶段状态
- 案件成员协作
- 争议焦点、代理目标、案件清单

### 2.3 证据中心

- 原始证据上传
- OCR / 文档解析
- 证据编号、分类、元数据管理
- 证据版本、证据引用关系、证据目录

### 2.4 质证书生成中心

- 证据组合选取
- 模板驱动生成
- AI 草拟与人工精修
- 多版本留痕

### 2.5 核验工作台

- 左侧 Word 风格成品文稿
- 右侧证据源原件查看器
- 句子级锚定
- 段落级核验状态、批注、回退、重绑

### 2.6 商业化运营

- 套餐、积分、订阅、企业合同
- 支付、发票、订单
- 使用统计、配额、风控

### 2.7 平台治理

- 审计日志
- 操作留痕
- 敏感数据脱敏
- 告警、监控、备份、恢复

## 3. 目标系统架构

```text
Web / Electron / 管理后台
        |
   API Gateway / BFF
        |
-------------------------------------------------
| Auth | Organization | Case | Evidence | Billing |
-------------------------------------------------
| Certificate | Review | OCR | LLM Orchestrator  |
-------------------------------------------------
| PostgreSQL | Object Storage | Queue | Cache     |
-------------------------------------------------
| Audit | Metrics | Trace | Backup | Alerting     |
-------------------------------------------------
```

## 4. 推荐技术栈

### 4.1 前端

- React + TypeScript
- 路由与状态管理拆分
- Web 与 Electron 共用业务层
- 文档工作台独立模块化

### 4.2 后端

- Node.js + TypeScript
- 模块化单体优先，后续按服务边界拆分
- 版本化 API
- DTO 校验、统一错误、审计日志、权限中间件

### 4.3 数据与基础设施

- PostgreSQL：核心业务数据
- Redis：会话、缓存、限流
- 对象存储：PDF、Word、图片原件
- 队列：OCR、转码、LLM 异步任务
- OpenSearch / PostgreSQL FTS：全文检索

## 5. 关键非功能需求

### 5.1 安全

- RBAC + 组织隔离
- JWT / Session 双方案
- 数据加密与脱敏
- 审计日志不可篡改

### 5.2 性能

- 证据上传走分片 / 直传
- OCR 与 LLM 任务异步化
- 大文件预览走转码与缓存
- 高并发查询依赖索引与读写分离策略

### 5.3 稳定性

- 全链路日志
- 健康检查与 readiness 检查
- 失败重试与死信队列
- 定期备份与恢复演练

## 6. 当前代码阶段与本次落地内容

当前代码已经从原来的单文件演示接口，升级到更适合商用演进的基础骨架：

- 新增环境配置校验
- 新增统一请求上下文与 request id
- 新增安全中间件与压缩中间件
- 新增版本化 API：`/api/v1`
- 新增统一错误响应结构
- 保留旧版 `/api` 接口以兼容现有前端
- 新增 PostgreSQL 迁移目录：`server/migrations`
- 新增组织、成员、RBAC、审计日志的数据表
- 新增文件上传与对象存储抽象，当前默认落本地存储

### 6.1 已落地的商用接口

- `POST /api/v1/iam/register`
- `POST /api/v1/iam/login`
- `GET /api/v1/iam/me`
- `GET /api/v1/organizations/current/members`
- `POST /api/v1/organizations/current/members`
- `POST /api/v1/files/upload`
- `GET /api/v1/audit-logs`

### 6.2 启用 PostgreSQL 的方式

1. 配置 `server/.env` 中的 `DATABASE_URL`
2. 执行 `npm run migrate`
3. 启动后端服务

如果需要在服务启动时自动迁移，可将 `AUTO_RUN_MIGRATIONS=true`
