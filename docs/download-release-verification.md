# 下载与安装发行验收

## 已实现

- 网页代理双向流式转发，保留文件长度、Range、ETag 和原始响应字节。
- 用户取消下载时取消上游传输；中途失败关闭连接，不伪装成完整文件。
- 版本接口提供真实 SHA256，按文件大小和修改时间缓存；文件变更自动重算。
- 下载页可展开校验值，并下载 `.sha256` 文件。
- 增加以 `.exe` 结尾的哈希静态地址和长期缓存能力，但公网全文件验收未通过，
  因此没有将它作为默认下载源。
- 支持通过 `RELEASE_DOWNLOAD_BASE_URL` 切换到独立 HTTPS 下载源；
  未配置时保持现有下载地址，配置后旧地址也会跳转到独立下载源。
- ETag 使用真实文件哈希，安装包不匹配时拒绝错误续传。
- 缺失安装包不返回演示版本，也不把旧版本地址偷偷指向新版本。
- 签名构建强制签名，并验证安装器和客户端的有效签名及时间戳。

## 回归测试

在仓库根目录执行：

```powershell
npm.cmd --prefix web run test:proxy
npm.cmd --prefix cloud-server run test:download
npm.cmd --prefix cloud-server run test:download -- --base http://127.0.0.1:4273
npm.cmd --prefix cloud-server run test:download -- --base https://lawagent.zhijing.fun --resume-only
```

测试检查元数据、HEAD 文件长度、完整下载、分段续传后的 SHA256、
无效范围的 416 响应和不存在版本的 404 响应。`--resume-only` 仍下载全部
安装包，只是不再重复执行一次全量下载。测试下载流不落盘。

代理测试额外检查首块即时发送、压缩内容、Cookie、POST 请求体、
客户端取消、上游断流和响应超时。

## 发布步骤

1. 配置有效代码签名证书，执行 `npm.cmd --prefix app run build:desktop:signed`。
2. 检查安装器和客户端签名状态为 `Valid`，且存在时间戳。
3. 同一版本的文件不可覆盖；修订安装包时提升版本号。复制发布产物时先用
   非 `.exe` 临时文件名，复制完成后再改为最终文件名，避免下载半成品。
4. 构建官网和云端服务，通过 `platform-dev.cmd restart` 更新运行进程。
5. 执行本机及公网下载回归测试。
6. 在独立 Windows 测试机上，通过官网实际下载，核对 SHA256，再验证安装、
   启动、登录和旧版本升级。不要在生产服务器静默安装替代验收。

普通构建不是已签名商业发行包。签名不能保证立即消除所有 SmartScreen
警告；不得以关闭系统安全防护作为解决办法。

## 尚需外部配置

- 代码签名证书：当前机器未发现可用证书，已有安装包仍未签名。
- CDN：面向主要用户所在地区部署对象存储和 CDN，再切换下载源。
  需要存储账号、下载域名和相应凭据，不在没有真实服务的情况下生成备用链接。
  现有 Cloudflare 已实测缓存命中，但尾段传输仍出现超时，不能仅凭
  `CF-Cache-Status: HIT` 认定分发稳定。本机上行网络、
  Cloudflare 隧道和主机休眠仍会影响未独立托管的文件。

## 独立下载源接入

1. 创建真实对象存储桶及 HTTPS 下载域名，允许公开读取安装包，
   但写入权限仅授予发布身份。
2. 上传原始安装包，对象键为 `<SHA256>/LawVerify-Setup-<版本>.exe`。
   如配置的下载基础地址含目录，则将对象放入对应目录。
3. CDN 配置应保留 Content-Length、Range、ETag 和 Content-Disposition，
   二进制响应设置 `Cache-Control: public, max-age=31536000, immutable, no-transform`。
4. 验证对象存在后，在 `cloud-server/.env.local` 配置真实
   `RELEASE_DOWNLOAD_BASE_URL`，不要设置为空字符串，也不要写入示例域名。
   再重启服务并执行公网回归测试，核对最终 SHA256。
5. 发布者凭据保存在本机安全配置中，不进入仓库、不发到聊天中；
   云端服务只需要公开下载基础地址，不需要对象存储写入密钥。

## 用户报错判断

- 文件大小或 SHA256 不一致：重新下载，不运行损坏的安装包。
- 未知发布者或 SmartScreen：检查有效签名和发布者信誉。
- 校验一致、签名有效但仍无法安装：收集 Windows 版本、报错截图及安装日志，
  在独立测试机复现后处理，不能仅凭下载修复认定安装问题已解决。
