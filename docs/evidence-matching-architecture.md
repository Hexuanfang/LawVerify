# LawVerify 证据匹配与核验顶层架构

## 目标

把 `lawVerify` 从“证据列表 + 文书编辑器”升级为真正可商用的“主张-证据匹配与核验系统”。

系统最终要支持：

1. 接入多种证据源：Word、PDF、图片、录音、截图、结构化附件。
2. 把证据统一解析为可定位、可引用、可匹配的证据片段。
3. 把文书中的句子、段落拆为可核验主张。
4. 让系统自动找出支持、部分支持、冲突或证据不足的候选证据。
5. 在中间文书与右侧原件预览之间形成逐句核验闭环。

## 总体分层

### 1. 证据接入层

- 本地文件夹链接
- 单文件导入
- 批量更新与替换
- 后续扩展：录音、视频、聊天导出包、邮件、压缩卷宗

### 2. 多模态解析层

- Word / PDF：结构解析、页码和段落定位
- 图片：OCR、版面结构、区域框选
- 录音：ASR、说话人、时间戳
- 复杂截图：视觉理解补强

### 3. 标准化建模层

统一沉淀三类核心对象：

- `EvidenceFragment`
  - 证据片段
  - 是右侧预览和引用定位的最小单元
- `ClaimUnit`
  - 文书中的可核验主张
  - 是系统做逐句核验的最小单元
- `ClaimEvidenceMatch`
  - 主张和证据片段之间的关系
  - 支持 `support / partial / contradict / unrelated / insufficient`

### 4. 匹配推理层

分两段执行：

1. 候选召回
   - 关键词召回
   - 向量召回
   - 元数据过滤
2. 精判
   - 使用 LLM / 多模态模型判定证据与主张关系
   - 输出理由、引用摘录、定位和置信度

### 5. 人工核验层

- 点击文书某句 -> 右侧展示候选证据
- 切换支持 / 冲突 / 证据不足
- 人工确认后写回 `ClaimEvidenceMatch`
- 最终形成“可解释、可追溯”的引用链

## 当前已落地的骨架

本次已把以下核心结构接入工作区模型：

### `EvidenceFragment`

字段目标：

- `evidenceId`
- `fragmentType`
- `sourceKind`
- `locator`
- `text`
- `summary`
- `keywords`

当前实现：

- Word / 文本：按段级片段切分
- PDF：按页级片段切分
- 图片：按 OCR 语句块切分
- 当前仍属于启发式切分，后续会替换为真正的 OCR / ASR / 版面结构解析结果

### `ClaimUnit`

字段目标：

- `certificateId`
- `paragraphId`
- `sentenceIndex`
- `text`
- `normalizedText`
- `labels`
- `status`

当前实现：

- 先按段落句子切分生成主张单元
- 后续会接入事实主张抽取和法律要件分类

### `ClaimEvidenceMatch`

字段目标：

- `claimUnitId`
- `evidenceFragmentId`
- `relation`
- `score`
- `reason`
- `quote`
- `locator`
- `source`
- `verified`

当前实现：

- 先从已有人工 `EvidenceLink` 自动派生基础匹配关系
- 同时按主张关键词自动召回同案候选证据片段，并结合数字锚点、否定信号和事实动词做规则精排
- 让当前系统已有“证据绑定”能自然升级为“主张-证据匹配”

## 运行时主干流程

### A. 证据导入

1. 导入原始文件
2. 生成 `Evidence`
3. 自动生成基础 `EvidenceFragment`
4. 当前已支持按证据类型做启发式细分：
   - PDF 页片段
   - Word / 文本段片段
   - 图片 OCR 片段
5. 后续再接入更高精度的异步解析：
   - 图片 OCR 框与坐标
   - 录音时间片段
   - 复杂版面和表格结构

### B. 文书生成/导入

1. 生成或导入 `Certificate`
2. 段落切句，生成 `ClaimUnit`
3. 若段落已有人工证据绑定，则同步生成 `ClaimEvidenceMatch`
4. 若段落暂无足够人工绑定，则自动补充启发式候选匹配

### C. 智能匹配

当前已具备第一版“候选召回 + 规则精排”，后续继续升级：

1. 输入 `ClaimUnit`
2. 从 `EvidenceFragment` 中召回候选
3. 使用模型判定关系
4. 输出候选 `ClaimEvidenceMatch`
5. 人工确认后写回正式链路

## 模型与能力规划

### 第一类：解析模型

- OCR：图片/扫描件/截图文字识别
- ASR：录音转写
- 视觉模型：聊天截图、票据、表格、手写区域理解

### 第二类：召回模型

- Embedding
- Reranker
- 基于当事人 / 时间 / 证据类型的元数据过滤

### 第三类：推理模型

- 主张抽取
- 匹配判定
- 冲突检测
- 匹配理由生成

## 后续实施顺序

### 阶段 1：主干完成

- 证据片段化
- 文书主张化
- 主张与人工证据绑定打通

### 阶段 2：解析增强

- 图片 OCR 坐标化
- PDF 页内段落切片
- Word 原生结构切片
- 录音 ASR + 时间戳

### 阶段 3：智能匹配

- 启发式候选召回升级为向量 / rerank 召回
- LLM 精判
- 置信度和解释理由

### 阶段 4：核验工作台升级

- 逐句核验面板
- 支持 / 冲突 / 证据不足切换
- 原件高亮定位
- 匹配结果可追溯审计

## 设计原则

1. 先按最终商用目标设计，不以演示版思路裁剪核心能力。
2. 先打主干，再扩展多模态深度能力。
3. 所有模型输出都要落到结构化对象，而不是只返回一段自然语言。
4. 所有匹配都必须支持人工复核和来源追溯。
