# 功能缺口补齐与验收

## 实现范围

| 缺口 | 实现 | 入口 |
| --- | --- | --- |
| 文书中废止法条标红 | 编辑器直接高亮废止版本；修订版本给出风险提示；编辑后旧结论立即失效 | 文书正文、右侧法条核验 |
| 查不到法条提示未能核实 | 缺失法律、缺失具体条文、占位正文、多版本不明均不判定为核实成功；支持中文条号、并列条号及条之编号 | 右侧法律引用核验 |
| 案号真伪核验 | 分别检查格式、同案号记录与法院官方具体页面；只有官方正文包含对应案号才显示已核实；查询失败不判定为虚假 | 右侧法条或案例核验 |
| 法官、法院加权检索 | 联查配置的案例供应商，保留外部语义召回，叠加可调法院和法官权重；法官姓名来自明确的审判人员字段 | 右侧案例面板 |
| 埋点 | 用户主动开启；事件白名单；去重、每日限额、管理员汇总；关闭后删除该用户已上传事件 | 客户端账户、官网账户资料、管理端使用统计 |
| 邀请奖励 | 邀请链接、注册绑定、邀请人数与获奖积分；真实合格付款后双方入账；事务及幂等键防止重复奖励 | 客户端账户、官网账户资料、注册页 |

风险高亮采用编辑器装饰，不修改文书正文，也不将核验提示插入正式导出的文书。可见文稿的本地检查串行执行，不对每一段自动发起付费外部检索。

## 核验边界

- 法律检查使用本地法源记录；“核对官方来源”尝试刷新全国人大法源。已知废止、修订版本的警告不会因找到新版本而被抹除。
- 法律引用的版本、适用时间与案件条件仍须律师判断；找到法源不等于该引用适用于本案。
- 案号格式正确、案例供应商返回同号记录、法院门户首页均不足以确认真实性。官网正文无法公开访问、需要登录、发生超时或来源无具体页面时，保留“未能核实”。
- 外部案例库需要配置及相应授权；未配置时明确显示仅检索本地案例。未经授权的供应商不能保证覆盖所有案号或审判人员。
- 单段上限 30,000 字；一次在线检查最多 20 个不同法条引用、10 个案号，整体截止时间 90 秒。超时返回已完成结果及未完成提示。

## 邀请奖励规则

发奖默认关闭，避免未经确认产生积分成本。实现的可配置参考规则：

```dotenv
REFERRAL_REWARDS_ENABLED=false
REFERRAL_INVITER_POINTS=100
REFERRAL_INVITEE_POINTS=50
REFERRAL_MIN_PAYMENT_FEN=1000
```

开启后，新账号注册时绑定有效邀请码；首次达到门槛的真实已支付订单触发一次奖励。门槛为人民币分，`1000` 表示 10 元。模拟支付、未付款及未达门槛的订单不触发奖励。

旧账号不能事后绑定邀请关系。注册、邀请码绑定、注册赠送和会话创建在同一 PostgreSQL 事务中；奖励与订单结算在同一事务中。发奖使用 `referral:<被邀请用户ID>:inviter/invitee` 唯一键，双方奖励记录关联触发订单，账户页显示实际累计奖励。

本次未增加充值退款或活动奖励撤销机制；如之后开放付费退款，必须同时设计对应奖励追回规则。

## 埋点隐私

仅允许固定事件名、事件 UUID、客户端类型、成功或失败及耗时。不接收案件名、文件名、文书正文、检索词、联系方式或任意自定义字段。

默认不开启；服务端检查授权，不依赖客户端开关决定是否保存。撤回授权与事件删除事务化处理，阻止并发上传重新留下记录。每用户每天最多 1,000 条，写入时清理超过 90 天的事件。管理员页面仅汇总近 30 天功能次数、失败次数与平均耗时。

登录事件由云端产生；支付完成事件使用订单 UUID 去重。自动本地法条检查不计作用户主动在线核验。统计失败不阻断登录、编辑、核验或支付业务。

## 部署要求

本次完成源码实现与本地验证，未变更生产数据库、未重启生产云端服务、未重新发布安装包。已有未提交的稳定性改动保留。

部署云端新版本前，执行新增数据库迁移 `008_referrals_analytics.sql`：

```powershell
npm --prefix cloud-server run migrate
```

按已确认的活动规则配置邀请奖励开关及金额。随后按现有部署流程发布云端、官网和客户端；旧安装包不会自动包含本次客户端功能。
