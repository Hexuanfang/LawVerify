# LawVerify · 文书类型 × 元素拆解清单（v1.2 开发规格）

> 交付对象：技术。可直接按本文 + `doc-element-profile.json` 实现。
> 上游：`产品文档/LawVerify 产品 v1.2-PRD.md` §3.3、§4.3。
> 配套：`02-核验Benchmark与达标判定.md`、`00-开发总纲.md`。

## 0. 结论：不同文书类型**需要**对应的元素拆解清单

**答案：需要。** 不能继续用 `src/utils/review.js` 里那份全局 `ELEMENTS`（12 类 × 固定 A/B/C 维度）一把梭。

四个理由：

1. **PRD 只给了全集，没给每类文书的子集。** 十类文书共用 12 类声明，但起诉状不该拆质证，证据清单不该拆法条，上诉状不拆就会漏掉"空泛指错"。
2. **律师核验重点随文书变。** PRD §2 的顺序（能不能出事 → 缺什么 → 稳不稳 → 润色）在不同文书上落点不同：证据清单看幽灵证据和目的越界；上诉状看指错定位与判项反转；代理词看旧法时效和类案命中。
3. **现有演示数据已经隐含了分型。** `cases.js` 里 `zj` 只有 E-EVID/E-PURP，`ss` 以 E-ERR 为主，`db` 以 E-CROSS 为主——只是代码没把这件事显式化。
4. **AutoClaw legal 的做法是先定型再抽。** `legal-element-extraction` 先切九类事实单元再对应要件；`legal-document-summarization` 先识别文书类型再选模板。核验管线应当同构。

**落地方式**：引入 `DOC_PROFILES[docKey]`，抽取器只抽 `required + optional`，`off` 类型抽出来算误报。机器可读配置见同目录 `doc-element-profile.json`。

## 1. 三档拆解级别

| level | 含义 | 漏抽后果 | 误抽后果 |
| --- | --- | --- | --- |
| `required` 必拆 | 该文书律师必然要看的话 | 计重大缺陷（漏拆），进 benchmark 扣分 | 正常 |
| `optional` 选拆 | 出现才拆，不出现不罚 | 不扣 | 正常 |
| `off` 不拆 | 该文书不应出现这类声明 | 不扣 | 计误报，进 benchmark 扣分 |

金标集标注时，`required` 元素在该文书没有对应内容可以标 `N/A-无内容`，不算漏拆；有内容没抽到才算漏拆。

## 3. 配置契约（技术实现）

### 3.1 类型定义

```ts
type Level = 'required' | 'optional' | 'off';
type DocKey = 'qs'|'db'|'zj'|'zz'|'dlc'|'ss'|'zs'|'lsh'|'flyj'|'proc';
type ElementType = 'E-SUBJ'|'E-CLAIM'|'E-FACT'|'E-CALC'|'E-EVID'|'E-PURP'
                 |'E-LAW'|'E-CASE'|'E-FOCUS'|'E-PROC'|'E-CROSS'|'E-ERR';
type CheckCode = 'A1'|'A2'|'A3'|'A4'|'A5'|'B1'|'B2'|'B3'|'B4'|'B5'|'B6'
                |'C1'|'C2'|'C3'|'C4'|'C5'|'C6'|'C7';

interface ElementRule {
  level: Level;
  checks: CheckCode[];      // 该文书该元素要跑的检查项
  hint: string;             // 抽取提示，喂给模型/规则
}

interface DocProfile {
  name: string;
  alias?: string[];         // proc <- cx
  position: string;         // 律师核验重点，决定待办排序权重
  identityElements: ElementType[]; // 身份元素完整清单，JSON 已内建
  elements: Record<ElementType, ElementRule>;
  minExpect?: Partial<Record<ElementType, number>>; // 抽样底线；漏拆分母是全部 required
}

/** 声明抽取标记：off 误报 / required 漏拆 由评测器写入，不进业务 store */
type ExtractFlag = 'ok' | 'off_fp' | 'required_fn';

// docKey 归一：cx -> proc
const DOC_KEY_ALIAS: Record<string, DocKey> = { cx: 'proc' };
```

### 3.2 加载与查询

```ts
import profile from './doc-element-profile.json';
// 落位：本 JSON 的 source of truth 在 产品文档/开发交付/，开发时拷贝到 src/data/doc-element-profile.json。
// 改配置先改开发交付目录，再同步拷贝，不要反过来。

export function profileFor(docKey: string): DocProfile {
  const key = DOC_KEY_ALIAS[docKey] ?? docKey;
  return profile.profiles[key];
}

export function levelOf(docKey: string, type: ElementType): Level {
  return profileFor(docKey).elements[type].level;
}

/** 替换 review.js 现有 checksFor：按文书类型取 checks，而不是全局 ELEMENTS 的 AB/ABC 串 */
export function checksFor(item: { type: ElementType }, docKey: string) {
  const rule = profileFor(docKey).elements[item.type];
  return rule.checks.map((code) => ({
    code,
    name: profile.dimensionChecks[code],
    status: item.checks?.[code] || '未核实',
  }));
}
```

### 3.3 对现有代码的改造点

| 位置 | 现状 | 改法 |
| --- | --- | --- |
| `src/utils/review.js` `ELEMENTS` | 全局 12 类 → 固定维度组 | 保留作 fallback；新管线读 `doc-element-profile.json` |
| `src/utils/review.js` `checksFor` | 用 `ELEMENTS[type][1]` 展开整组 | 改为 `checksFor(item, docKey)`，只跑 profile 勾的码 |
| `src/data/cases.js` | 演示数据已按文书分型 | 不动；金标集另行扩 |
| 抽取入口（生产管线） | 无 | 新增 `extractStatements(doc, profile)` |
| 待办排序 | 全局红灯优先 | 同红灯下按 `profile.position` 里的身份元素加权 |

## 4. 通用抽取规则（所有文书共用）

来自 PRD §4.3 + AutoClaw `legal-element-extraction`。

### 4.1 切句与定位

- 输入：DOCX / TXT / Markdown 段落树；生产补 OCR + 版面坐标。
- 每条声明必带：`id`、`type`、`quote`、`loc`（第 N 段 / 表格第 R 行 C 列）。
- 一句混合（请求 + 法条 / 事实 + 计算）**拆两条**，各自挂类型。
- 证据清单**按行**抽 `E-EVID` / `E-PURP`，证明目的单独一条。
- 抽不出的整段不硬拆；保留为 `E-NOTE`（不进核验，只进报告"未识别段"）——本期可先不实现 E-NOTE，直接跳过。

### 4.2 九类事实单元（E-FACT 切分提示）

AutoClaw `legal-element-extraction` 的九类，作为 E-FACT 的抽取 checklist：

| 事实类型 | 核心问题 | 示例（c1） |
| --- | --- | --- |
| 主体 | 何人 | 原告王某、被告李某 |
| 行为 | 做了什么 | 3月15日转账 50 万 |
| 时间 | 何时 | 2023-03-15 / 2023-04-11 |
| 地点 | 何地 | 北京朝阳区（管辖） |
| 对象 | 指向什么 | 借款本金 500,000 元 |
| 结果 | 产生什么后果 | 至今未还本金 |
| 因果 | 行为→结果 | 转账交付 → 借贷关系成立 |
| 主观 | 主观状态 | 承认欠款（"钱我认"） |
| 程序 | 程序行动 | 催告、起诉 |

**四分法净化**（抽之前先过一遍）：

| 属性 | 处理 |
| --- | --- |
| 客观事实 | 保留，标可能的 L1 来源 |
| 主观判断（"我觉得""显然"） | 剥离情绪，追问背后事实 |
| 法律评价（"构成欺诈""属于违约"） | 还原为支持评价的客观事实，评价本身不单独成 E-FACT |
| 背景信息 | 剔除 |

红线：**不虚构缺失事实**。评价语（欺诈、恶意、违约）不能直接当分析前提——这正是 c1-z2 "承认欠款→欺诈" 越界红灯的抽取侧原因。

### 4.3 空泛指错与幽灵证据

- 空泛指错（"一审认定事实错误"无页码/段落）→ `E-ERR` + `miss` 缺源，不硬凑定位。
- 幽灵证据（清单有、卷内无）→ `E-EVID` + `miss`。
- 攻击不存在的证据 → `E-CROSS` + `fail`。

### 4.4 不确定就 pending

模型抽取置信度低、或 `optional` 边界模糊时，宁可 `pending` 也不猜类型。`pending` 阻断导出，符合铁律。

## 5. 逐文书规格

> 每类文书：定位 → 身份元素 → 逐元素规则 → 漏拆/误拆 → 演示集示例。
> 判定细则（pass/warn/fail/miss）统一见 `02-核验Benchmark与达标判定.md` §5，此处只写"查什么"。

### 5.1 起诉状 qs

**律师看什么**：请求能否成立、事实有无凭据、法条是否现行、金额能否复算、管辖对不对。

**身份元素**：E-CLAIM、E-FACT、E-LAW、E-CALC、E-PROC、E-SUBJ。

| 元素 | 级别 | 查什么 | 示例 |
| --- | --- | --- | --- |
| E-SUBJ | 必 | 姓名/名称、住所与身份证/户籍/工商一致 | c1-subj 身份已定位，提交版查脱敏 |
| E-CLAIM | 必 | 每项请求挂请求权基础；漏基础 = B6 遗漏 warn | c1-q6 民法典 675/577 |
| E-FACT | 必 | 九类事实单元；日期金额主体与 L1 逐项比对 | c1-q1 借条+流水互证 pass；c1-q4 4月1日/3万 vs 4月11日/3.5万 fail |
| E-CALC | 必 | 必须给算式 `基数 × 利率 × 期间 ÷ 365`；只写结果 = warn | c1-q2 利息未列算式 warn |
| E-LAW | 必 | B1 存在 / B2 效力 / B3 逐字 / B4 要件 / B5 层级 / B6 遗漏 | 旧法+新事实 = fail + 替代条文（见 dlc c1-l4） |
| E-PROC | 必 | 管辖连接点（民诉法24 + 解释18）、时效 | c1-cx 相关 |
| E-EVID | 选 | 正文点名证据才抽 | — |
| E-CASE / E-FOCUS | 选 | 出现才拆 | — |
| E-PURP / E-CROSS / E-ERR | 不拆 | 抽出来算误报 | — |

**minExpect**：E-SUBJ≥1，E-CLAIM≥1，E-FACT≥2，E-LAW≥1。

### 5.2 答辩状 db

**律师看什么**：抗辩有无证据、对方诉请有没有被歪曲、自洽性（别自己打自己）。

**身份元素**：E-CROSS、E-CLAIM、E-SUBJ、E-FACT、E-LAW。

| 元素 | 级别 | 查什么 | 示例 |
| --- | --- | --- | --- |
| E-CROSS | 必 | 对对方诉请/事实/证据的回应，转述与对方文书对应 | c1-d1 自洽矛盾 fail；c1-d3 无异议=与起诉状对应 pass |
| E-FACT | 必 | 抗辩事实 + A5 自洽 | c1-d2 流水一致 pass |
| E-LAW | 必 | 抗辩权基础效力与要件 | c1-d4 民法典 674 pass |
| E-CLAIM | 必 | 驳回/部分驳回/反诉 | — |
| E-CALC | 选 | 已付、抵扣、违约金调整 | — |
| E-EVID | 选 | 提交反证 | — |
| E-FOCUS / E-PROC | 选 | 程序抗辩、争点归纳 | — |
| E-PURP / E-ERR | 不拆 | — | — |

**minExpect**：E-SUBJ≥1，E-CLAIM≥1，E-CROSS≥1。

**典型红灯**：c1-d5 "原告曾口头同意免除剩余利息" 无聊天/函件/录音 → miss，建议删除或补原始载体。

### 5.3 证据清单 zj

**律师看什么**：幽灵证据、目的越界、反向漏登。

**身份元素**：E-EVID、E-PURP。其余基本不拆。

| 元素 | 级别 | 查什么 | 示例 |
| --- | --- | --- | --- |
| E-EVID | 必 | 每行一条；清单↔卷内双向；卷内无 = 幽灵 miss | c1-z1 借条对应 pass；c1-z3 证人证言卷内无 miss |
| E-PURP | 必 | 证明目的单独一条；A4 不得超出证据内容 | c1-z2 "承认欠款"推不出"欺诈" fail，advice 改目的 |
| E-FACT / E-CALC / E-SUBJ | 选 | 金额证据行、来源主体 | — |
| 其余 | 不拆 | 法条/案例/质证/指错出现在清单里算误报 | — |

**minExpect**：E-EVID≥2，E-PURP≥1。

**反向漏登**：卷内有《原告身份证.jpg》《被告户籍信息.pdf》未列清单 → `warn`（c1-z4），不阻断导出。

### 5.4 质证意见 zz

**律师看什么**：有没有攻击不存在的证据、质疑真实性却无瑕疵点、转述加戏。

**身份元素**：E-CROSS、E-EVID。

| 元素 | 级别 | 查什么 | 示例 |
| --- | --- | --- | --- |
| E-EVID | 必 | 先确认对方证据存在，再质。演示集 zz 三条均为 E-CROSS，E-EVID 由金标集补 | — |
| E-CROSS | 必 | 三性意见逐证一条；质疑真实性须落具体瑕疵 | c1-t1 转述一致 pass；c1-t2 "可能被篡改"无定位 warn；c1-t3 攻击不存在证据 fail |
| E-FACT | 选 | 转述证据内容须一致 | — |
| E-LAW / E-PROC / E-PURP | 选 | 证据规则、申请鉴定、攻击目的越界 | — |
| E-CLAIM / E-CASE / E-ERR | 不拆 | — | — |

**minExpect**：E-EVID≥1，E-CROSS≥1。

### 5.5 代理词 dlc

**律师看什么**：论证链断没断、旧法有没有失效、类案是不是严格命中。

**身份元素**：E-FOCUS、E-FACT、E-LAW。

| 元素 | 级别 | 查什么 | 示例 |
| --- | --- | --- | --- |
| E-FOCUS | 必 | 双方争点，不混我方立场 | — |
| E-FACT | 必 | 事实论证，多源互证 | c1-l1 借条+转账 pass |
| E-LAW | 必 | 时间效力重点 | c1-l2 民法典 667 pass；c1-l4 合同法 107 + 2023 事实 fail，替代 577 |
| E-CASE | 选 | detail 前不引判项；上游事实未核实 → 严格命中降近似类比 | c1-l3 严格命中 pass，dependsOn c1-l4 C6 |
| E-CLAIM | 必 | 重申请求 | — |
| E-CROSS / E-ERR / E-CALC | 选 | 回应对方 / 二审指错 / 损失算式 | — |
| E-PURP | 不拆 | — | — |

**minExpect**：E-FACT≥1，E-LAW≥1，E-FOCUS≥1。

**级联**：c1-l4 失效 → 依赖它的 c1-l3 类案 C6 时效性重开。

### 5.6 上诉状 ss

**律师看什么**：指错有没有定位、原审认定有没有被反转、上诉请求对应民诉法 177 哪一档。

**身份元素**：E-ERR、E-CLAIM、E-LAW、E-PROC、E-SUBJ。

| 元素 | 级别 | 查什么 | 示例 |
| --- | --- | --- | --- |
| E-ERR | 必 | 每处指错一条；定位到页/段/本院认为；转述与原审逐字 | c1-s1 定位一致 note；c1-s2 "分文未付" vs 原审已付 3.5 万 fail；c1-s3 空泛指错 miss |
| E-CLAIM | 必 | 撤销/改判/发回 对应 177 | c1-s4 民诉法 177 pass |
| E-LAW | 必 | 二审程序法 + 实体修正 | — |
| E-PROC | 必 | 上诉期、上诉费 | — |
| E-FACT / E-CASE / E-CROSS | 选 | — | — |
| E-EVID / E-PURP | 不拆 | 新证据另附 | — |

**minExpect**：E-SUBJ≥1，E-CLAIM≥1，E-ERR≥1，E-LAW≥1。

### 5.7 再审申请书 zs

**律师看什么**：是否落在民诉法 207 事由、新证据、原审认定反转。

**身份元素**：E-ERR、E-CLAIM、E-LAW、E-PROC、E-FOCUS、E-SUBJ。

与上诉状差异：
- E-FOCUS 从选升**必**（再审争点 = 原审漏审/错认的点）。
- E-EVID 选（新证据是 207 事由之一，出现才拆）。
- E-PROC 必查六个月期限、上一级/本级管辖。

演示集 c1-zs 是 pending 占位，金标集需补完整样本。

**minExpect**：E-CLAIM≥1，E-ERR≥1，E-LAW≥1。

### 5.8 律师函 lsh

**律师看什么**：事实有没有凭据、要求是否明确带期限、引法是否现行。对外函更容易写评价语。

**身份元素**：E-CLAIM、E-FACT、E-LAW、E-SUBJ。

| 元素 | 级别 | 查什么 |
| --- | --- | --- |
| E-CLAIM | 必 | 催告/解除/索赔/停止侵权，一项一条，带期限 |
| E-FACT | 必 | 客观事实；A4 别把"再不还就起诉"写成"你方恶意逃废债" |
| E-LAW | 必 | 解除权/违约责任/时效中断 |
| E-CALC | 选 | 金额必须可复算 |
| E-PROC | 选 | 送达方式、后果告知 |
| E-CROSS / E-ERR / E-PURP / E-FOCUS | 不拆 | — |

**minExpect**：E-SUBJ≥1，E-CLAIM≥1，E-FACT≥1，E-LAW≥1。

### 5.9 法律意见书 flyj

**律师看什么**：争点清不清楚、法律分析有没有失效条文、结论有没有超出事实。

**身份元素**：E-FOCUS、E-FACT、E-LAW、E-SUBJ。

| 元素 | 级别 | 查什么 |
| --- | --- | --- |
| E-FOCUS | 必 | 表述为可回答的法律问题 |
| E-FACT | 必 | 意见书最容易把假设当事实，缺源标 L0 |
| E-LAW | 必 | LOW 置信度不得作确定结论（借 legal-norm-validity-check） |
| E-CASE | 选 | 严格命中 vs 近似类比必须标 |
| E-CLAIM | 选 | 建议方案 |
| E-CROSS / E-ERR / E-PURP | 不拆 | — |

**minExpect**：E-FOCUS≥1，E-FACT≥1，E-LAW≥1。

### 5.10 程序类文书 proc（别名 cx）

**律师看什么**：程序法条对不对、连接点事实有没有、层级（法律 vs 解释）。

**身份元素**：E-PROC、E-CLAIM、E-LAW、E-SUBJ。

| 元素 | 级别 | 查什么 | 示例 |
| --- | --- | --- | --- |
| E-PROC | 必 | 异议期、移送、保全担保 | — |
| E-CLAIM | 必 | 管辖异议/保全/回避 | c1-cx 请求审查地域管辖 |
| E-LAW | 必 | 民诉法 24、解释 18；B5 层级 | — |
| E-FACT | 选 | 合同履行地、住所地、签收地 | — |
| E-ERR | 选 | 对裁定指错须定位 | — |
| E-CALC / E-EVID / E-PURP / E-FOCUS | 不拆 | — | — |

**minExpect**：E-SUBJ≥1，E-CLAIM≥1，E-LAW≥1，E-PROC≥1。

## 6. 待办排序权重（profile.position 的用法）

PRD §2 顺序在文书内的落地：同分状态下，身份元素排前面。

```
排序键 = (verdict 权重, 身份元素加权, 段落序)
verdict 权重: fail=0, miss=1, pending=2, warn=3, note=4, pass=5

```

示例：
