# LawVerify · 核验 Benchmark 与达标判定（v1.2 开发规格）

> 交付对象：技术 + 测试。用于判定核验是否**达标**。
> 上游：PRD §1 铁律、§3 核验模型、§4 管线、§10 导出闸门。
> 配套：`01-文书类型元素拆解清单.md`、`doc-element-profile.json`。
> 借鉴：AutoClaw `legal-qa`（输出前门禁）、`legal-norm-validity-check`（效力 7 态 + 置信度）、`legal-article-retrieval`（Recall/Precision）、`case-retrieval`（五维相似度）。

---

## 0. 这份文档怎么用

1. **开发前**：按 §1 红线自检管线设计；按 §5 实现每条检查项的判定函数。
2. **开发中**：用 §3 金标集跑分，命令与输出格式见 §8。
3. **交付前**：§7 分档表定 达标 / 基本达标 / 不达标；一票否决项任何一条命中即不达标。
4. **验收时**：审阅方按 §8 报告模板核对，不接受"效果不错"这类定性说法。

**判定原则**：核验是否达标，不看 UI 好不好看，只看三件事——
该拆的拆到了没有（抽取）；该红的红了没有（判定）；不该编的编了没有（铁律）。

## 1. 一票否决红线（任何一条命中 = 不达标）

借 `legal-qa` + PRD 三条铁律，以下行为出现**一次**即判不达标，不允许用平均分掩盖：

| 编号 | 红线 | 判定方法 |
| --- | --- | --- |
| R1 | **编造案号 / 法条 / 法院 / 日期** | 金标集里每条 E-LAW / E-CASE 与库内/MCP 返回比对；库里没有却给出条号原文或案号要旨 = R1 |
| R2 | **缺源假装已联动** | L0 声明的 sources 非空、或 UI 显示 L1/L2/L3 色 = R2 |
| R3 | **引号内与原文不一致** | `quote` 中引号内文字 vs 库内 `text` / 判决原文，去空白逗号句号后不等 = R3 |
| R4 | **判项反转 / 原审认定反转** | 把"已付 35,000"写成"分文未付"这类；支持/驳回、连带/补充性质写反 = R4 |
| R5 | **导出闸门失效** | 存在 fail / miss / pending 时审阅版或清洁版仍可导出 = R5 |
| R6 | **失效法条未标失效** | 库内 `st=已废止` 或 MCP 返回非现行有效，核验结果仍 pass = R6 |
| R7 | **用相似出处补位** | L1 查无却挂了同名不同期、或用学理通说当法条原文 = R7 |
| R8 | **把要旨写成判项原文** | E-CASE 引号内标榜"判项"但 detail 全文无此句 = R8 |
| R9 | **AI 产出直接 pass** | 助手起草 / 改写 / MCP 引用入正文后 verdict ≠ pending = R9 |
| R10 | **MCP 失败静默编造** | 工具超时/空结果后仍输出"依据《XX法》第N条…" = R10 |

红线测试用例见 §3.3 对抗样本，**必须全过**。

## 2. 评测对象与口径

### 2.1 评什么

| 层 | 输入 | 输出 | 指标 |
| --- | --- | --- | --- |
| 抽取 | 文书原文 + docKey | 声明列表 `{id,type,quote,loc}` | 召回率、精确率、类型准确率、定位准确率 |
| 核验 | 声明 + L1/L2/L3 | `verdict` + `checks` + `sources` + `reason` | 逐维准确率、检出率、误报率 |
| 联动 | 上游 verdict | 下游级联 | 级联触发率 |
| 闸门 | 全文书状态 | 可否导出 | 闸门正确率 |
| 助手 | 指令 + 上下文 | 草稿/MCP 卡 | 产出 pending 率、缺源不编造率 |

### 2.2 状态枚举（与 PRD §3.2 一致）

```
pass   绿·通过           不阻断
note   通过·标注         不阻断（人工核验通过，保留标注）
warn   黄·预警           不阻断，留报告
miss   红·缺源           阻断
fail   红·不通过          阻断（矛盾/失效/失真/越界/编造）
pending 待核验            阻断（新导入/AI产出/修改后未重核）
```

`blocksExport = fail || miss || pending`。

**状态词表**：判定器与 benchmark 用英文枚举 `pass / note / warn / fail / miss / pending`；`cases.js` 与 UI 的中文（通过/不通过/预警/缺源）是展示层映射，不得反向当成判定器输入。

置信度 `conf` 是辅助展示，**不参与达标判定**；判定以规则命中为准。AutoClaw 效力检查的 HIGH/MEDIUM/LOW 映射：

| AutoClaw 置信度 | LawVerify 处理 |
| --- | --- |
| HIGH | 可直接出 pass / fail |
| MEDIUM | 最高只能 warn，不得 pass（除非人工 note） |
| LOW | 不得作为确定性结论；E-LAW 落 warn 或 pending，提示换替代条文 |

## 4. 指标体系与公式

### 4.1 抽取层

以金标集人工标注为真值。

| 指标 | 公式 | 达标线 | 优秀 |
| --- | --- | --- | --- |
| 必拆召回 R_req | TP_req / (TP_req + FN_req) | ≥ 0.95 | ≥ 0.98 |
| 总体召回 R_all | TP / (TP + FN) | ≥ 0.90 | ≥ 0.95 |
| 精确率 P | TP / (TP + FP) | ≥ 0.85 | ≥ 0.92 |
| 类型准确率 Acc_type | 类型正确的 TP / TP | ≥ 0.92 | ≥ 0.97 |
| 定位准确率 Acc_loc | 段位正确的 TP / TP | ≥ 0.90 | ≥ 0.95 |
| off 误报率 FPR_off | off 类型被抽出 / off 应为 0 的机会 | ≤ 0.05 | ≤ 0.02 |

说明：
- TP = 类型正确且 quote 与标注重叠（去空白后编辑距离 ≤ 20% 或完全包含）。
- FN = 标注了 required/optional 却没抽到。**R_req 分母是该文书全部 required 元素实例，不是 minExpect**；minExpect 只作抽样底线。
- FP = 抽出了 off 类型、或同一句重复抽、或类型错且未拆分。
- 混合句未拆（请求+法条一条）计 1 个 FN + 1 个 FP。
- 评测器在声明上写 `extractFlag: 'ok' | 'off_fp' | 'required_fn'`，不进业务 store。

### 4.2 核验层

以金标集期望 verdict / checks 为真值。

| 指标 | 公式 | 达标线 | 优秀 |
| --- | --- | --- | --- |
| 总体判定准确率 Acc_v | verdict 一致数 / 总声明 | ≥ 0.90 | ≥ 0.95 |
| 红灯检出率 DR_red | 检出 fail+miss / 实际 fail+miss | ≥ 0.95 | = 1.00 |
| 红灯误报率 FR_red | 误判为 fail+miss / 实际非红 | ≤ 0.08 | ≤ 0.03 |
| 黄灯命中率 DR_warn | 检出 warn / 实际 warn | ≥ 0.80 | ≥ 0.90 |
| 缺源不编造率NF | L0 仍标 L0 / 实际 L0 | **= 1.00** | = 1.00 |
| E-LAW 六查全跑率 | B1–B6 都有结果 / E-LAW 总数 | ≥ 0.95 | = 1.00 |
| E-CASE 四要素完整率 | 案号+法院+日期+定位 齐 / E-CASE 总数 | ≥ 0.95 | = 1.00 |
| E-CALC 算式给出率 | 给出 基数×利率×期间 / E-CALC 总数 | ≥ 0.95 | = 1.00 |
| 级联触发率 Casc | 上游红/待 → 下游重开 / 应触发数 | ≥ 0.95 | = 1.00 |
| 闸门正确率 Gate | 导出允许/阻止 与预期一致 | **= 1.00** | = 1.00 |

**NF 与 Gate 是硬约束**，达不到 1.00 直接不达标（与 §1 R2/R5 对应）。

### 4.3 检索层（L2 / L3，接真实 MCP 后启用）

借 `legal-article-retrieval` 的基线并收紧（核验场景比检索报告更严）：

| 指标 | 公式 | 达标线 | 说明 |
| --- | --- | --- | --- |
| 法条查全 R_law | 命中应引条文 / 应引全集 | ≥ 0.85 | 请求权基础不得漏 |
| 法条查准 P_law | 正确条文 / 返回候选 | ≥ 0.70 | 候选给律师选 |
| 效力判定准确 Acc_val | 7 态一致 / E-LAW | ≥ 0.98 | 废止/现行不允许错 |
| 案例严格命中区分 Acc_hit | 严格命中 vs 近似类比 标对 | ≥ 0.90 | 不得以类比冒充命中 |
| 判项引用前 detail 率 | 引判项前调过 detail / 引判项数 | **= 1.00** | 硬约束 |

效力 7 态（与 AutoClaw 对齐，落 `checks.B2` 附注）：
`VALID 现行有效` / `AMENDED 已修正` / `PARTIAL 部分失效` / `REPEALED 已废止` / `EXPIRED 已失效` / `PENDING 尚未生效` / `UNCERTAIN 效力存疑`。

双轨核验：`legal_statute article_detail`（或演示库）为主锚；涉时效边角走官方页（flk.npc.gov.cn）。双轨都不确定 → UNCERTAIN → warn，不得伪装 pass。

### 4.4 助手 / 起草层

| 指标 | 公式 | 达标线 |
| --- | --- | --- |
| 产出 pending 率 | AI 草稿/MCP 引用入正文为 pending / 总产出 | = 1.00 |
| 起草带证据关联率 | 草稿声明挂到 L1/L2/L3 候选 / 草稿声明 | ≥ 0.80 |
| 缺源不编造（助手） | 未命中明说未找到 / 未命中次数 | = 1.00 |
| 立场为空拦截 | 立场空时起草被拦截提示 | = 1.00 |

## 5. 逐维度判定细则（A / B / C）

技术按此实现判定函数。**每条给出 pass / warn / fail / miss 的充分条件**。

### 5.1 A 组 · 溯源性（L1 为主）

| 码 | 名称 | pass | warn | fail | miss |
| --- | --- | --- | --- | --- | --- |
| A1 溯源 | 卷内找到同名材料/同义表述/日期金额主体 | 命中且主体对 | 只命中部分要素 | — | 卷内无任何对应 |
| A2 一致 | 日期、金额、主体、性质逐项比 | 全 ok | 单项 mid（如截图传来） | 任一 bad → diff 表 | — |
| A3 完整 | 清单↔卷内双向 | 双向齐 | 反向漏登（卷内有清单无） | — | 清单有卷内无（幽灵） |
| A4 边界 | 证明目的 vs 证据内容 | 目的⊆内容 | 目的略宽但可修 | 目的推出证据没有的定性（欺诈/恶意） | — |
| A5 自洽 | 同段/全文 | 无矛盾 | — | 前后冲突（此后未再付 vs 4/11 付款） | — |

**金额复算**（挂在 E-CALC 的 A2+B3）：
- 必须输出算式：`基数 × 利率 × 期间天数 ÷ 365`（或约定计息方式）。
- 算不出 / 只写结果 → warn。
- 算式与流水对不上 → fail + diff。

**diff 表格式**（fail 时必给，不许模糊措辞）：

```
| 要素 | 文书 | 原材料 |
| 日期 | 2023-04-01 | 2023-04-11 |
| 金额 | 30,000 元 | 35,000 元 |
```

### 5.2 B 组 · 真实有效（L2 为主）

| 码 | 名称 | pass | warn | fail | miss |
| --- | --- | --- | --- | --- | --- |
| B1 真实 | 条号在库存在 | 存在且名称对 | — | 库内无此条（编造） | 未检索（pending） |
| B2 有效 | 施行日 ≤ 事实日 ≤ 废止日 | 现行有效 | UNCERTAIN / PENDING / 过渡期 | REPEALED / EXPIRED 且事实在新法期 | — |
| B3 准确 | 引文 vs 库内逐字（去空白逗号句号） | 相等 | 转述且标"要旨归纳" | 引号内不等 | 只给条号无原文 |
| B4 适配 | 要件匹配 | 借款返还配 675 | 部分要件待补 | 借款配买卖 / 二审配一审条文 | — |
| B5 层级 | 法律 > 司解 > 规章 | 层级标对 | 同位阶冲突已说明 | 把规章当法律 / 地方法规适用外地 | — |
| B6 遗漏 | 请求权基础 | 基础齐 | 缺一项提示（不代补） | — | 整个请求无基础 |

**B2 替代条文**：判 fail 时必须给 `verifiedText` + `verifiedSources`（如 107 → 577），律师一键换后局部重核。

**禁止**（命中即降级或 R1/R7）：
- 只给条号不给原文
- 把学理通说当法条
- 用境外法解释大陆现行法
- 规范性文件（红头文件）当裁判依据（可说理 → warn）

### 5.3 C 组 · 类案（L3 为主）

| 码 | 名称 | pass | warn | fail | miss |
| --- | --- | --- | --- | --- | --- |
| C1 真实 | 案号真实、要旨与判决一致 | detail 命中 | — | 案号不存在 | 未检索 |
| C2 可回查 | 法院+日期+页码/本院认为 | 四要素齐 | 缺页码但有法院日期 | — | 无法定位 |
| C3 准确 | 四要素命中度 | 案由/主体/关键事实/争议 ≥3 | =2 | ≤1 还称严格命中 | — |
| C4 相关 | 严格命中 vs 近似类比 | 标对且与事实一致 | 标近似 | 把类比标成严格命中 | — |
| C5 层级 | 指导性>公报>高院参考>普通 | 标对 | 升格/降格一格 | 把普通案例说成指导性 | — |
| C6 时效 | 所引旧法已废止 | 所依法律现行 | 类案依废法，降近似 | — | — |
| C7 去重 | 同案多引 | 合并 | — | 同案计两条充数 | — |

**五维相似度**（借 case-retrieval，用于 C3/C4 打分）：

```
法律关系一致 30% + 争议焦点对应 25% + 关键事实相似 25% + 裁判规则参照 15% + 程序问题关联 5%
≥ 0.75 且法律关系一致 → 严格命中
0.50–0.75 或法律关系不一致 → 近似类比（黄）
< 0.50 → 不相关，不入正文
```

**联动**：上游 E-FACT pending/fail → C4 由严格命中降近似类比（c1-q7 dependsOn c1-q1）。

**地位标签**：指导性 / 公报 / 高院参考 / 普通，以检索返回字段为准，不得升格。

## 6. 级联降级与导出闸门

### 6.1 级联规则（PRD §3.4）

| 上游 | 下游 | 动作 |
| --- | --- | --- |
| E-FACT fail/miss/pending | 依赖它的 E-LAW | B4 适配性重开，可降 pending |
| E-FACT fail/miss/pending | 依赖它的 E-CASE | C4 严格命中 → 近似类比（warn） |
| E-LAW B2 失效 | 依赖它的 E-CASE | C6 时效重开，论证链断裂 |
| 律师处理上游 | 下游 | 局部重核 dirty 集 |

测试：把 c1-q1 改成 pending，c1-q7 必须从 pass 降为 warn 近似类比。

### 6.2 导出闸门

| 交付物 | 允许导出条件 |
| --- | --- |
| 审阅版 Word（原生批注） | 无 fail / miss / pending |
| 清洁版 + 核验报告 | 同上 |
| 案例检索报告 Word | **不阻断**（检索交付，不是文书外发） |

黄灯可忽略并留报告。人工 note 不阻断。

测试：c1 起诉状（有 fail/miss）→ 两种文书 Word 按钮禁用 + 文案说明；案例报告可导。

## 8. 评测流程

### 8.1 跑分命令（建议）

```bash
# 技术实现 CLI，读取 benchmark/gold 与 expected
npm run bench -- --set all --out benchmark-report.json
# 分层
npm run bench -- --set seed        # c1+c2 种子
npm run bench -- --set adversarial # ADV-01~12
npm run bench -- --set extra       # 扩充集
```

### 8.2 步骤

1. **种子集回归**：c1/c2 全部关键点与 `cases.js` 一致。不一致 = 管线错，先修再谈达标。冲突时以 `cases.js` 为准。
2. **对抗集**：ADV-01–12 全过。任一红线命中即停，修红线。
3. **抽取分**：只开抽取，关核验，算 R/P。
4. **核验分**：喂标准声明（跳过抽取误差），算 Acc_v / DR / FR。
5. **端到端**：原文进 → 报告出，算全套。
6. **人工抽检**：随机 30 条 pass 与 30 条 fail，律师复核。人工推翻率 > 15% 则该档指标作废重标。

### 8.3 报告模板（人读版）


## 9. 与 AutoClaw legal 能力的对齐清单

技术实现核验函数时，以下规则**必须**内化（不是参考）：

| LawVerify 检查 | AutoClaw 来源 | 内化要求 |
| --- | --- | --- |
| R1 不编案号法条 | `legal-qa` §1 / `yuandian` 红线 | 检索未命中 = miss/pending，不生成 |

| 案例四要素 | `legal-qa` §1 | C2 缺项 = warn 或 miss |
| 付费库不作唯一路径 | `legal-qa` §1 | 报告给官方库自查指引 |
