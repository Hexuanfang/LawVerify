### 3.2 生产 skill JSON 契约（技术后端用）

PRD §6.3 结构，技术按此实现可插拔配置。生产契约以 `skills.prod.json` 为准（本文示例省略 url 字段）。

**两个 guard 的语义不要混**：
- `forbidFabricate`：全局只读 `true`，任何技能、任何团队配置都不得关。缺源不编造是铁律。
- `needLawyerConfirm`：会写入正文或导出的技能（draft / rewrite / statute-mcp / case-mcp / case-report / inbox-search）必须 `true`；分析卡（evidence / chain / calc / risk / focus / timeline）可为 `false`，因为它们不下结论、只列短板。

```json
{
  "id": "statute-mcp",
  "name": "法条 MCP",
  "group": "检索",
  "tools": ["legal_statute"],
  "system": "只回现行有效与已废止替代；引文逐字；缺源不编。效力状态用 7 态枚举；UNCERTAIN 不得伪装现行有效。",
  "output": { "type": "citation-card", "require": ["law_name", "article_number", "validity", "text"] },
  "guard": { "forbidFabricate": true, "needLawyerConfirm": true }
}
```

本期不需要把 AutoClaw 的 17 个方法论 skill 拷进仓库——它们是运行时能力。技术要做的是把上表约束写进对应 skill 的 system 与输出校验。

## 4. MCP 参数契约（生产接入时对齐）

演示层 `src/utils/mcp.js` 本期保留。生产替换时保持以下最小契约，UI 不改：

```ts
// 法条
callLegalStatute({
  action: 'semantic' | 'search_article' | 'article_detail',
  query?, law_name?, article_number?, refer_date?, validities?, top_k?
}) => { items: [{ law_name, article_number, text, validity, effective_date, repeal_date?, url, id }] }

// 案例
callLegalCase({
  action: 'semantic' | 'keyword' | 'detail',
  query?, case_number?, id?, causes?, courts?, authoritative?, top_k?
}) => { items: [{ case_number, name, court, judgment_date, level, gist, url, id }] }
```

硬规则（写进适配层，不是写进提示词完事）：
1. 引用原文/判项前必须 `article_detail` / `detail`。
2. 非现行有效必须标。
3. 引用附返回 `url`（skills.prod.json 已要求；上文 TS 返回示例已含）。
4. 未命中返回空数组 + 明确 `miss`，不返回"相似条"补位。
