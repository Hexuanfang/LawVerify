## 1\. 背景与目标

### 1\.1 背景

民商事诉讼律师写完文书后，需要逐段核对事实是否来自卷内材料、法条是否现行有效、案例是否真实且真这么判。人工核对耗时、易漏、易被 AI 生成内容的幻觉坑。现有法律 AI 侧重生成，核验与溯源能力弱。

### 1\.2 产品定位

不替律师写文书、不下法律结论。只做一件事：**把文书中每一句事实、每一条法条、每一个案例，联动到案件原材料、法律法规库、案例库中的具体出处，分档判定，让律师确认后带着批注导出。**

### 1\.3 产品目标

律师在系统里完成「上传 → 核验 → 逐段看依据 → 点材料看原件 → 确认/换源 → 导出带批注 Word」的闭环。

- **可溯源**：每条标注可点击回到文书原文与源头原文位置

- **一致性**：事实、法条、案例表述与源头是否匹配

- **关联性**：证据与证明目的、论证链是否支撑

- **不编造**：查无出处就报缺源，绝不用相似出处补位

- **可编辑**：律师确认、修改、补充后导出带批注的 Word

---

## 2\. 用户与场景

**主要用户**：民商事诉讼律师、律师助理、律所质控人员
**次要用户**：企业法务（内部案件文书核验）

**核心场景**：

1. 律师上传起诉状 \+ 案卷材料，系统标出诉讼请求、事实、法条与原材料的对应关系及问题点

2. 质证阶段上传质证意见，系统检查与证据清单、对方证据的一致性（转述不得走样）

3. 代理词定稿前，系统检查论证链是否完整、案例是否真实、法条是否现行有效

4. 上诉状指错必须能定位到一审判决对应段落

5. 导出带 AI 批注 \+ 人工确认记录的 Word，用于内部复核或归档

## 3\. 产品范围

### 3\.1 本期做（In Scope）

- 6 类民商事核心文书：**起诉状、答辩状（含反诉）、证据清单、质证意见、代理词、上诉状**

- 三类证据源联动：**案件原材料 L1、法律法条 L2、案例 L3**

- 核验流水线：抽取声明 → 定位源头 → 逐项比对 → 四档判定

- 交互：原文高亮 \+ 右侧四 Tab \+ 人工确认/换源

- 导出：审阅版 Word（批注）\+ 清洁版 \+ 核验报告

- 支持打印件与清晰扫描件（OCR）；手写件本期不做（见 3\.2）

- 案例库三源：元典、威科先行、北大法宝

- 法条库：民商事常用范围，效力以国家法律法规数据库为权威锚

### 3\.2 明确不做

|**不做**|**原因**|
|---|---|
|自动生成或修改法律结论|只提示，不替代判断|
|刑事、行政、非诉文书的定制规则|复用通用标准，不单独设计|
|手写文书 OCR 作为可靠输入|误字会污染事实核验；清晰扫描优先|
|实时多用户协作编辑|一期单编辑者 \+ 只读分享|
|胜诉率预测或策略建议|—|
|在中栏直接改稿|改稿回 Word，核验只读原文|

## 4\. 名词与核心概念

### 4\.1 三类证据源

|编码|名称|内容|定位键|
|---|---|---|---|
|**L1**|案件原材料|用户上传的合同、流水、发票、聊天记录、函件、身份材料、庭审笔录、**对方文书、一审判决**|材料 ID \+ 页码/条款/时间戳/段落|
|**L2**|法律法条|法律、司法解释、行政法规、地方性法规、规章、会议纪要|法律 ID \+ 条文号|
|**L3**|案例|指导性案例、公报案例、普通判例|案号|

**L1 特别说明**：对方起诉状/答辩状、一审判决书、庭审笔录都属于 L1。质证意见联动对方证据、上诉状联动一审判决，走 L1，不另立第四类源。

### 4\.2 十二种内容元素

解析器把任何文书拆成以下 12 种元素，一个元素 = 一次联动单元：

|**编码**|**元素**|**默认联动**|
|---|---|---|
|E\-SUBJ|主体身份|L1|
|E\-CLAIM|请求/抗辩|L2 为主，L1 辅|
|E\-FACT|事实陈述|L1|
|E\-CALC|数额计算|L1 \+ L2|
|E\-EVID|证据项|L1 一一对应|
|E\-PURP|证明目的|L1（目的⊆内容）|
|E\-LAW|法条引用|L2|
|E\-CASE|案例引用|L3|
|E\-FOCUS|争议焦点|L1\+L2\+L3|
|E\-PROC|程序事项|L2 为主|
|E\-CROSS|对对方材料的回应|L1 对方证据|
|E\-ERR|对前审的指错|L1 前审文书段落|

### 4\.3 四档判定

|档位|含义|处理|
|---|---|---|
|**通过**|有据且一致，无效力问题|放行|
|**通过·标注**|有据但需注意（归纳/自认/旧法适用/类比案例/转引）|放行，卡片标黄签|
|**预警**|出处糊 / 要件缺一半 / 只有摘要 / 关联弱|提示复核|
|**不通过**|缺源 / 矛盾 / 越界 / 不存在 / 失效 / 失真 / 错配 / 虚构 / 无关 / 已推翻|强制人工处理，红灯|

> 不用绿黄红三档。三档会把"能用但要标注"和"必须复核"混在一起，对外文书无法区分能否发出。

### 4\.4 案件记忆

案件级全局上下文缓存，不随点击某段而重算。材料变更时提示"重新梳理"。核验每份文书时复用。

## 5\. 产品红线

1. **缺源不编造**：检索未命中只出"缺源"，不展示任何猜的出处。手动挂靠是用户行为，不是 AI 行为。

2. **引号内逐字一致**：引号内条文、判决说理、对方证据原文必须逐字一致；做不到改转述并标"要旨归纳"。

3. **判项不反转**：支持/驳回、连带/补充、认定/未认定以原文为准，不得美化或反转。

4. **质证反向一致**：转述对方证据与该证据原文逐字一致；攻击卷内不存在的证据 = 不通过。

5. **上诉指错必定位**：未定位到一审判决具体段落 = 不通过。

6. **案例四要素**：案件名称、案号、审理法院、裁判日期缺一不可；案号三库全查无 = 不通过，不用相似案例顶替。

7. **法条效力锁版本**：每次核验记录库版本号与检索时间点；已废止法条不得默认引用（行为发生在旧法期除外，须标注）。

8. **对外文书阻断**：法律意见书、律师函等对外文书存在任何不通过项时，禁止标记为终稿（本期 6 类文书导出仍放行，但报告顶部红条提示）。

9. **AI 仅辅助**：产品内显著提示"AI 仅辅助，最终责任在律师"；导出带核验声明。

## 7\. 功能需求

## 7\.1 上传与案件材料库

### 7\.1\.1 上传页

双区上传：左「案件原材料」、右「已撰写文书」。

- 拖拽或点击；原材料可批量，文书可批量

- 原材料格式：PDF、图片（JPG/PNG/HEIC）、Word、Excel、TXT、EML、聊天记录截图

- 文书格式：DOCX、PDF、TXT

- 两侧齐备，「AI 智能核验」按钮才点亮

- 重复文件按内容哈希去重

- 上传即后台解析/OCR，图片出"已识别文字"角标

- 点击文件卡即可预览，不必等核验完成

### 7\.1\.2 证据目录（左栏）

- 按业务分组：合同协议 / 资金往来 / 沟通记录 / 身份主体 / 前审文书 / 其他

- 显示当前案件材料总数（原型：42 份）

- 支持链接本地文件夹

- 搜索：文件名 \+ OCR 文本 \+ 已抽取要素（金额、日期、人名）

- 右键：预览 / 重命名 / 替换 / 移除 / 查看引用它的文书段落（反向联动）

- 移除被引用材料需二次确认并列出受影响文段

- 工作台内可补传，补传后可"重新核验"只跑增量

### 7\.1\.3 解析预处理

- 打印件与清晰扫描件：OCR \+ 版面分析，保留坐标用于定位

- 自动识别文书类型（6 类优先，其他走通用）

- 解析失败（加密/损坏/格式不支持）：文件卡红色角标 \+ 重试 \+ 失败原因

- 手写件：本期不支持作为可靠输入；如用户上传，标"手写件，结果仅供参考，置信度降权"

|**板块**|**内容**|

## 7\.3 数据底座

### 7\.3\.1 案例库（L3）

**三源并行**：元典、威科先行、北大法宝。不单选。

**入库必备字段**（缺一不入）：案件名称、案号、审理法院、裁判日期、文书类型、全文文本或全文 PDF、裁判要旨、判项、效力层级、入库时间、来源库。

**接入层规则**：

1. **案号归一化**：全角半角、空格、括号统一后作主键

2. **同案合并**：同一案件不同审级保留关联但不算重复计数；多源命中字段取并集

3. **取全文不取摘要**：只有摘要的打标 `摘要-only`，核验最多"通过·标注：转引未经原文核验"，不能出通过

4. **效力分层**：

    - L3\-1 指导性案例（应当参照）

    - L3\-2 公报案例 / 最高法典型案例

    - L3\-3 高院参考案例

    - L3\-4 普通案例

**冲突处理**：

|**情形**|**处理**|
|---|---|
|同一案多源全文不一致|以最接近官方裁判文书网/法院官网版本为准；无法校准 → 预警"多源不一致"|
|一源有全文一源只有摘要|用有全文的|
|指导性案例标识不一致|以最高人民法院发布为准|
|案号一源命中另源查无|取命中源；三源全查无 → 该引用不通过|
|被后续案例/新法推翻|任一源命中即打失效标|

**更新维护**：

|**机制**|**频率**|**内容**|
|---|---|---|
|增量拉新|每日|三源新收录按案号去重入库|
|指导性案例对账|每周|新发布 / 被替换 / 被撤销|
|推翻监测|每周|再审改判、新司法解释否定|
|法律变更联动|事件驱动|新法施行日扫描以其为依据的案例，标"裁判依据已变"|
|版本冻结|每次核验|锁定库版本号|

### 7\.3\.2 法律法条库（L2）

**一期范围**（民商事诉讼律师案头常用，不追求大而全）：

|**层级**|**范围**|
|---|---|
|法律|民法典及各编、民事诉讼法、公司法、票据法、保险法、海商法、企业破产法、产品质量法、消费者权益保护法；涉劳动争议启用劳动法/劳动合同法|
|司法解释|民法典配套（合同编通则、担保、物权、婚姻家庭、继承、侵权、时间效力规定）、民间借贷、建工、买卖合同、民事证据规定、民诉法解释、保全、执行异议|
|商事配套|公司法司法解释与 2023 修订配套、票据法解释、保险法解释|
|纪要|九民纪要等——标"非正式效力源"，不得作唯一依据|
|行政法规/规章|民商事高频（不动产登记暂行条例等），标层级|
|地方性法规|按案件地域按需启用（原型案在河北三河），标地域效力|
|暂不入场|刑法、行政规制类、地方规章全集|

**权威锚**：效力状态以**国家法律法规数据库**为准；北大法宝/威科/元典并行；不一致以国家库校准。

**效力状态机**（每条必备）：

```Plaintext
现行有效 / 已修正（挂最新文本）/ 部分失效 / 已废止（附替代映射）/ 已失效 / 尚未生效 / 效力存疑（不得作确定结论依据）
```

**新旧法衔接内置表**：

|**旧法**|**废止日**|**替代**|
|---|---|---|
|合同法、物权法、担保法、侵权责任法、民法通则、民法总则、婚姻法、继承法、收养法|2021\-01\-01|民法典对应编|
|公司法 2018|2024\-07\-01 起 2023 修订版施行|注意过渡条款|

**更新**：每日同步公布/修正/废止；新法施行日 00:00 切换效力；最高法司法解释清理即换版；每次核验记录法条库版本 \+ 检索时间点。

### 7\.3\.3 原材料库（L1）（agent 对话检索）

用户上传为主，系统做结构化抽取与时间线构建。必备能力：

- 文件级定位：页码 / 条款号 / 时间戳 / 段号

- 要素抽取：主体、日期、金额、行为（用于字段级匹配）

- 对方文书、一审判决的**段落级**索引（质证与上诉状依赖）

- OCR 文本与、原件坐标双存（预览时红框命中）

## 7\.4 核验流水线

```Plaintext
文书解析 → 切 12 种元素 → 按元素默认源检索候选出处
        → 字段级比对 → 四档判定 → 联动图谱
        → 全文一致性扫描 → 连坐传播 → 报告
```

### 7\.4\.1 抽取

- 按文书类型抽预定义字段（见附录字段映射表）

- 先抽强制字段，再抽非强制；抽取失败标"未识别"，不强行关联

- 区分声明与推论：评价性词（恶意/根本违约/欺诈/显失公平）不进事实核验，只核其基础事实

- 模糊引用（"根据相关法律规定""有类似判例"）必须抽出并判预警

### 7\.4\.2 定位与比对

**不是整段相似度，是字段对字段**：

|**元素**|**必须对上的字段**|
|---|---|
|E\-FACT|主体、时间、金额、行为|
|E\-CALC|基数、比率、期间、公式（结果可复算）|
|E\-EVID|证据名称/编号|
|E\-LAW|法律全称 \+ 条文号|
|E\-CASE|案号|
|E\-CROSS|对方证据编号 \+ 被质证的具体内容|
|E\-ERR|前审文书段落定位 \+ 原认定表述|

### 7\.4\.3 三类核验规则

#### L1 案件原材料

- 事实表述一致性（同一事实冲突 → 不通过）

- 时间线合理性（日期、签名、落款矛盾）

- 证明目的 ⊆ 证据内容（超出 → 不通过·越界）

- 完整性（引用但缺关键页/原件 → 预警）

- **质证反向一致性**：转述对方证据逐字一致

- 输出可疑点清单，不下法律结论

#### L2 法律法条

- 存在性：名称 \+ 条号真实

- 效力：现行有效 / 正确适用旧法 / 已废止 → 不通过并给替代条文

- 引文：引号内逐字一致

- 要件适配：法条要件与案件事实逐项对应

- 层级：上位法/特别法/新法；规章与纪要不得写成"依照本法"

- 遗漏：更直接的请求权基础未引 → 预警

#### L3 案例

- 四要素齐全且真实

- 要旨来自判决书全文，不是检索摘要

- 判项性质以原文为准

- 相似度分级：

    - **严格命中**：案由相同 \+ 核心争点相同 \+ 关键事实特征匹配

    - **近似类比**：部分匹配，必须说明差异点

    - **不相关**：不得引用

- 效力分层标注

- 未被推翻

- 同一案件不同审级不重复计数

- 严格命中为零时如实说明，不得以类比冒充命中

### 7\.4\.4 交叉核验

|配对|内容|
|---|---|
|文书引用法条 ↔ 案例实际适用法条|不一致预警|
|原材料事实 ↔ 起诉状/代理词事实|不一致不通过|
|证据清单证明目的 ↔ 质证意见三性评价|矛盾提示|
|诉讼请求 ↔ 证据证明目的|缺支撑预警|

不一致优先提示，不自动修正。质证意见的"质证对象 ↔ 证据清单编号"为 P0。

### 7\.4\.5 连坐传播

```Plaintext
事实缺源/矛盾 → 依赖该事实的法条要件降级 → 依赖该事实的案例降为近似类比
法条失效 → 以该条为依据的案例标"裁判依据已变" → 依赖该条的诉请标"请求权基础失效"
对方证据转述失真 → 该段质证结论整段预警
```

## 7\.5 六类文书联动规则

### 7\.5\.1 起诉状

|**内容**|**L1**|**L2**|**L3**|**强制**|
|---|---|---|---|---|
|当事人信息|身份材料|—|—|是|
|每条诉讼请求|金额依据|请求权基础|可引|是|
|金额计算|基数材料|计算法条|—|是（可复算）|
|事实时间线|逐笔溯源|—|—|是|
|法律关系定性|—|必引|可引|是|
|管辖|连接点|管辖条文|—|是|

### 7\.5\.2 答辩状 / 反诉状

|**内容**|**L1**|**L2**|**L3**|**强制**|
|---|---|---|---|---|
|对诉请的意见|对方起诉状原文 \+ 反证|抗辩权基础|可引|是|
|事实抗辩|逐笔|—|—|是|
|时效抗辩|起算点材料|时效条文|可引|是|
|反诉|同起诉状|同起诉状|同起诉状|是|
|管辖异议|连接点|程序法条|—|如有则强制|

### 7\.5\.3 证据清单

|**内容**|**联动**|**强制**|
|---|---|---|
|编号/名称|L1 一一对应|是|
|证明目的|L1，目的⊆内容|是（核心）|
|目录完整性|清单 ↔ 卷内 ↔ 文书引用 双向对齐|是|

案例在证据清单中通常不出现；出现才核。幽灵证据（清单有卷内无 / 卷内有清单无）双向报。

### 7\.5\.4 质证意见

|**内容**|**联动**|**强制**|
|---|---|---|
|质证对象|对方证据原文，编号可定位|是|
|真实性|载体/原件/对比材料|是|
|合法性|取证材料 \+ 证据规定|是|
|关联性|待证事实|是|
|证明力|可引案例（提示级）|否|

**红线**：转述对方证据与原文不一致 = 不通过；攻击不存在的证据 = 不通过。

### 7\.5\.5 代理词

|**内容**|**联动**|**强制**|
|---|---|---|
|争议焦点|双方诉辩原文|是|
|事实主张|逐笔 L1|是|
|法律适用|L2 要件全覆盖|是|
|类案参考|L3 四要素 \+ 相似度|是|
|论证链|事实→法条→\[案例\]→结论，断链=预警|是|
|请求重申|与起诉状/上诉状一致|是|

每个论点出论证链视图，断链节点标红。

### 7\.5\.6 上诉状

|**内容**|**联动**|**强制**|
|---|---|---|
|上诉请求|一审判决判项 \+ 上诉事由条文|是|
|事实认定错误|**一审判决具体段落** \+ 反证|是（未定位=不通过）|
|法律适用错误|一审所引法条 \+ 正确法条|是|
|程序违法|笔录/回证 \+ 程序法条|如有则强制|
|新证据|与原审材料区分|如有则强制|

三栏对照：一审认定原文 ｜ 上诉状转述 ｜ 反证材料。

## 7\.6 全文一致性

单段联动完成后全篇横向扫描。不替代三类联动。

|**编号**|**规则**|**判定**|
|---|---|---|
|C\-1|主体名称全篇一致；简称须建映射|未建映射出现新称谓 → 预警|
|C\-2|同一笔钱全篇数字一致；单位归一|不一致 → 不通过，出对照|
|C\-3|同一事件日期全篇一致；格式归一|不一致 → 不通过|
|C\-4|本案案号、引用案例案号、一审判决案号全篇一致|不一致 → 不通过|
|C\-5|证E编号在正文 ↔ 清单 ↔ 质证 三方对齐|幽灵编号 → 不通过|
|C\-6|同一文书不混用已废止法与现行法，除非写明行为在旧法期|混用无说明 → 不通过|
|C\-7|跨文书同一事实不矛盾（起诉状 vs 答辩状 vs 代理词 vs 上诉状）|矛盾 → 预警（可能是有意抗辩）\+ 定位差异|
|C\-8|代理词/上诉状请求与原请求不跑偏|跑偏 → 预警|
|C\-9|每个计算结果可复算；同一算式全篇同结果|复算不符 → 不通过|
|C\-10|引号内内容与所引原文逐字一致|走样 → 不通过|

不一致处两端标红，点任一端弹对照卡（文书A值 vs 文书B值 vs 原材料值），提供"以此为准"统一。

## 7\.9 人工确认闭环

|动作|效果|
|---|---|
|确认|锁定，重新核验不漂移，卡片绿✓|
|换源|打开材料/法条/案例选择器替换|
|标记问题|写备注，进报告"待人工处理"|
|忽略|不进报告统计，高亮退灰|

- 批量：筛"通过"一键确认；筛"不通过"逐条处理

- 进度：已确认 N / 总数 M

- 重新核验只重跑未确认元素

- 人工挂靠标"人工"，AI 不覆盖

- 替换原材料文件 → 受影响锁定联动解冻，提示重新确认

- 全部操作留痕：操作人、时间、变更内容，形成审计日志

- 红灯必须人工确认后才能标记"已核验"

- 用户可改元素类型（把误识别的评价改回事实），系统记住修正

**划词手动联动**（P1）：中栏划词 → 关联出处 → 选材料框选位置 → 建立"人工确认"联动。

## 10\. 风险与应对

|风险|影响|应对|
|---|---|---|
|OCR 清晰扫描仍有错字|事实核验误报|命中信置度低的 OCR 标"未核验"；差异对照让律师看原件|
|法条效力数据滞后|错误通过|国家库权威锚 \+ 核验锁版本 \+ 替代映射内置|
|三源案例冲突|律师不知道信谁|冲突处理规则写死（见 7\.3\.1）；多源不一致出预警不装一致|
|律师不信任 AI 标注|使用率低|红灯必人工确认；结果可解释（要素级对照不是分数）；可忽略本条|
|交叉核验误报|干扰阅读|交叉结果默认折叠，仅不通过强制展示|
|责任边界不清|法律风险|显著提示 AI 仅辅助；导出带核验声明；缺源不编造写进产品|
|模型用相似出处补位|假依据上庭|产品红线 \+ 验收指标"缺源误补率 = 0"|
|手写件用户硬传|定位失败|明示不支持；置信度降权；不进 P0|
