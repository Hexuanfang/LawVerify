## 1. 产品定位

LawVerify 不是通用法律大模型聊天窗，而是**律师办案台上的核验与起草工位**。

一句话：**把文书里的每一句可核验的话，钉到卷内材料、现行法条、在先判例上；钉不住的，不让它静默出稿。**

三条产品铁律（全期不变）：

1. **缺源不编造**：L1/L2/L3 查无，就标缺源，不用相似出处补位。
2. **AI 不替代律师**：所有 AI 产出一律「待核验」；导出闸门由红灯和待核验控制。
3. **可回查**：每条声明给出处、定位（页码/条款/时间戳）和命中/矛盾明细；引号内逐字一致；判项不反转。

### 两大主流程（并列，效果同权）

**目标 1 · AI 核验已有文书**
用户提供案件原材料 + 待核验文书 → AI 抽取声明、逐句核验、证据联动 → 律师在结果上修改、挂靠出处、批注 → 导出带批注的 Word。

**目标 2 · AI 起草新文书**
用户提供案件原材料 + 代理立场 → AI 结合原材料 + 法条 MCP + 案例 MCP 起草 → 同时展示证据关联结果 → 律师核验修改 → 导出链路与目标 1 完全一致。

**目标 3 · 案件记忆（横切）**
代理立场、律师笔记、争议焦点、时间线、金额台账、证据地图跨文书复用，供起草与核验参考。

## 2. 用户与核验工作重点

律师拿到一份文书（自己写的、助理写的、对方写的）时，真实工作顺序不是「从头读到尾」，而是：

1. **先看能不能出事**：事实写错、金额对不上、引用废法、空泛指错 → 必须改
2. **再看缺什么**：主张没有证据、幽灵证据、证明目的越界 → 补证或删
3. **再看稳不稳**：截图未公证、签收人身份、类案是否严格命中 → 预警，可选复核
4. **最后才看润色**：算式、措辞、清单对齐

v1.2 所有列表、报告、待办都按这个顺序组织，而不是按文书行文顺序平铺。

## 3. 核验模型（沿用并收紧）

### 3.1 信源四档

| 档 | 名称 | 色 | 说明 |
| --- | --- | --- | --- |
| L1 | 案件原材料 | 橙 | 合同、流水、聊天、身份、前审文书等卷内材料 |
| L2 | 法条 | 蓝 | 法规库快照 / legal_statute MCP；必须核效力 |
| L3 | 案例 | 青绿 | 类案库 / legal_case MCP；引用判项前必须 detail 全文 |
| L0 | 未联动 | — | 缺源；不允许假装已联动 |

### 3.2 状态六档与导出闸门

| 状态 | 含义 | 是否阻断导出 |
| --- | --- | --- |
| 红·不通过 | 矛盾 / 失效 / 失真 / 越界等 | **是** |
| 红·缺源 | 无出处 | **是** |
| 待核验 | 新导入 / AI 产出 / 修改后未重核 | **是** |
| 黄·预警 | 有据但有瑕疵 | 否；可忽略，留在报告 |
| 通过·标注 | 人工核验通过，保留标注 | 否 |
| 绿·通过 | 通过 | 否 |

**规则**：红灯 + 待核验 = 阻断两种 Word 导出。黄灯可忽略并保留在报告。审阅版生成原生 DOCX 批注；清洁版含正文 + 附页报告。

### 3.3 十二类声明与 A/B/C 维度

声明类型：`E-SUBJ 主体` `E-CLAIM 请求` `E-FACT 事实` `E-CALC 计算` `E-EVID 证据项` `E-PURP 证明目的` `E-LAW 法条` `E-CASE 案例` `E-FOCUS 焦点` `E-PROC 程序` `E-CROSS 质证` `E-ERR 前审指错`

维度组：

- **A 溯源性**：A1 溯源、A2 一致性、A3 完整性、A4 边界性、A5 自洽性
- **B 真实有效**：B1 真实性、B2 有效性、B3 准确性、B4 适配性、B5 层级性、B6 遗漏
- **C 类案**：C1 真实性、C2 可回查、C3 准确性、C4 相关性、C5 效力层级、C6 时效性、C7 去重

十类文书：起诉状、答辩状、证据清单、质证意见、代理词、上诉状、再审申请书、律师函、法律意见书、程序类文书。

### 3.4 联动降级

上游声明红 / 待核验时，依赖它的法条、类案**级联降级**：

- 事实未核实 → 法条适配性重开（可降为待核验）
- 事实未核实 → 类案由「严格命中」降为「近似类比」（黄）
- 旧法失效 → 依赖该法条的论证链断裂

律师处理上游后，下游需局部重核。

## 4. AI 智能核验处理规则（本期重点）

生产环境的核验管线分六步。原型中为演示动画；规则本身是产品规格，不是前端技巧。

### 4.1 管线

```
读取文书定位 → 抽取声明 → L1 匹配 → L2 匹配 → L3 匹配 → 分档与批注
```

### 4.2 第一步 · 读取与定位

- 输入：DOCX / TXT / Markdown（原型已支持文本层）；生产补 OCR、版面坐标
- 产出：段落树、表格、标题层级、每段坐标
- 规则：不重排原文；批注定位到段，不重写段

### 4.3 第二步 · 抽取声明

- 按十二类声明切句；一句混合请求 + 法条可拆两条
- 每条声明必带：`id`、`type`、`quote`、`loc`（第 N 段）
- 证据清单按行抽 `E-EVID` / `E-PURP`；证明目的单独一条
- 规则：抽不出的整段不硬拆；空泛指错（「一审认定事实错误」无定位）标缺源

### 4.4 第三步 · L1 原材料匹配（A 组为主）

对每条事实 / 计算 / 证据项：

1. **溯源**：在卷内找同名材料、同义表述、日期金额主体
2. **一致性**：日期、金额、主体、性质逐项比对；不一致出 diff 表
3. **完整性**：清单 ↔ 卷内双向对齐（反向漏登也报）
4. **边界性**：证明目的不得超出证据内容（「承认欠款」推不出「欺诈」）
5. **自洽性**：同段内「此后未再付」 vs 后文付款，报矛盾

命中标注：`ok` / `mid` / `bad`；`bad` 进 diff，不给模糊措辞。

**金额复算规则**：凡 `E-CALC`，必须给出 基数 × 利率 × 期间 ÷ 年化 的算式；算不出就黄灯，不许只写结果。

### 4.5 第四步 · L2 法条匹配（B 组为主）

1. **真实性**：条号在库内存在
2. **有效性**：施行日 ≤ 文书事实日 ≤ 废止日；废止必须给替代条文
3. **准确性**：引文与库内逐字一致（去空白逗号后比对）
4. **适配性**：要件匹配（借款返还 vs 买卖交付 vs 二审处理）
5. **层级性**：法律 > 司法解释 > 部门规章；同位阶冲突要说明
6. **遗漏**：请求权基础缺失要提示，不代替律师补法条

**时间效力**：旧法 + 新事实 = 红灯；给替代条文让律师一键换（如合同法 107 → 民法典 577）。

**禁止**：只给条号不给原文；把学理通说当法条；用境外法解释大陆现行法。

### 4.6 第五步 · L3 类案匹配（C 组为主）

1. **真实性**：案号真实、要旨与判决一致
2. **可回查**：给法院、日期、页码/本院认为定位
3. **准确性**：四要素（案由、主体关系、关键事实、争议）命中度
4. **相关性**：严格命中 vs 近似类比，必须标
5. **效力层级**：指导性 / 公报 / 高院参考 / 普通
6. **时效性**：所引旧法已废止的类案降级
7. **去重**：同案多引合并

**联动**：上游事实待核验 → 类案由严格命中降为近似类比。

**禁止**：编案号；把要旨写成判项原文；用类案反推事实。

### 4.7 第六步 · 分档与人工闭环

分档后进入工作台。律师可：

| 动作 | 条件 | 结果 |
| --- | --- | --- |
| 采纳修改建议 | 有 `verifiedText` | 替换 quote，局部重核 |
| 修改声明 | 任意 | quote 变更，转待核验 |
| 关联出处 | 缺源 | 手动挂 L1/L2/L3，转待核验 |
| 人工逐项核验 | 待核验且有摘录+定位 | 勾完 A/B/C 维度 → 通过·标注 |
| 批注 | 任意 | 进本句卡 + 审阅版 Word |
| 忽略预警 | 仅黄灯 | 不阻断导出，留报告 |
| 删除此句 | 缺源 | 从正文移除，报告留痕 |
| 局部重核 | 编辑态 | 只重核 dirty 声明 |
| 全文重核 | 编辑态 | 重核全部；已人工确认且未改的项不漂移 |

每次操作写审计：时间、律师名、动作。

### 4.8 修改后重核的判定（`evaluateEdit`）

1. 修改文本（去空白逗号句号）=== `verifiedText` → 通过，bad 命中项清除
2. 特例（演示 c1-q4）：继续比对日期金额，仍不一致 → 红灯 + 新 diff
3. 其余 → 待核验，理由「这段内容已变更，等待重新核对原文和依据」
4. 手动挂靠的出处标 `manual`，重核不自动清掉

### 4.9 全文重核不漂移

全文重核跳过「已人工确认 且 不在 dirty 集 且 非 pending」的声明。防止律师刚确认完又被演示逻辑打回。

## 5. AI 助手规则（本期重点）

### 5.1 定位

助手是**可指挥的办案副驾**，不是装饰聊天窗。三种指挥方式并存：

1. **自然语言**：自动路由到 检索 / 法条 / 案例 / 起草 / 改写
2. **能力锁存**：点上方能力条，后续输入强制走该工具
3. **技能包**：点「更多」弹层里的技能，填入 starter 问题

#### 能力区精简（v1.2.1）

常驻只留高频四项 + 有选中文段时的改写，其余 12 个技能包收进右侧「更多」弹层，避免标签墙：

| 常驻 | 说明 |
| --- | --- |
| ✦ 自动 | 按意图分发 |
| 📖 法条 MCP | `legal_statute` |
| ⚖️ 案例 MCP | `legal_case` |
| ✍️ 起草 | 立场 + 证据 → 新文书 |
| 🪄 改写 | 仅当选中文段时出现 |
| ⋯ 更多 | 卷内检索 / 证据三性 / 论证链 / 金额复算 / 争议焦点 / 时间线 / 风险 / 案例报告 |

### 5.2 能力条（常驻）

| 能力 | 图标 | 行为 |
| --- | --- | --- |
| 自动路由 | ✦ | 按意图分发 |
| 卷内 L1 | 📁 | 只搜案件原材料 |
| 法条 MCP | 📖 | 调 `legal_statute` |
| 案例 MCP | ⚖️ | 调 `legal_case` |
| 起草 | ✍️ | 立场 + 证据 → 新文书或补写 |
| 改写 | 🪄 | 改写选中文段；无选中则提示 |

### 5.3 意图路由（自动模式）

优先级从上到下：

1. 工具锁存优先于自然语言
2. `案例检索报告 / 导出案例 / 打包案例` → 案例检索报告
3. `起草/撰写/写/拟/生成` + 文书名 → 起草新文书
4. `法条/条文/第N条/效力/废止/民法典/请求权基础` → 法条 MCP
5. `案例/类案/判例/案号/（20xx）` → 案例 MCP
6. `改写/重写/润色/精简/更严谨` → 改写（需选中）
7. `依据/凭证/找一下/出处` → 卷内检索
8. 续聊（再/那/还有）沿用上一轮模式
9. 兜底：提示可选动作，不瞎猜

**起草 vs 补写**：没选中 → 新建草稿文书；有选中 → 插入到该声明后。

### 5.4 输入框自适应（对齐 AutoClaw）

- 默认单行（约 38px）
- 随内容增高，`height = min(scrollHeight, 176px)`
- 超过 176px 出滚动条
- Enter 发送，Shift+Enter 换行，IME 组合中不发送
- 发送后高度回落

### 5.5 上下文

助手自动携带：

- 选中文段（可移除）
- 当前文书 / 案件
- 案件记忆：代理立场、笔记、争议焦点、案情摘要
- 选中声明的类型与现有出处

起草时**必须**读代理立场；立场为空则提示去案件记忆填写。

### 5.6 产出纪律

1. AI 改写 / 起草 / MCP 引用，一律 `verdict = pending`，`aiOrigin` 标注
2. 不直接覆盖已通过声明，除非用户点「接受修改 / 替换」
3. MCP 结果可「引用到正文」「关联当前声明」「预览」，入正文前不过核验不算数
4. 卷内检索未命中，明确说未找到，并建议切 MCP；不用编的出处补位
5. MCP 未命中，同样缺源不编造

### 5.7 触发入口（本期扩充）

| 入口 | 位置 | 默认能力 |
| --- | --- | --- |
| 划词浮层 | 选中文段上方 | 问 AI / 改写 / 查法条 / 查案例 |
| 文书区工具条 | 标签行上方 | ✎ 在线编辑 / ✦ AI 助手 / AI 核验（贴正文，不再漂在全局右上角） |
| ＋ 起草新文书 | 文书区工具条左侧 | 起草 |

## 7. MCP 接入规范

### 7.1 本期原型

独立 HTML **未接真实 MCP**。`src/utils/mcp.js` 为演示适配层：

- `callLegalStatute` 查示例法条库（含阿拉伯数字→汉字条号）
- `callLegalCase` 查示例案例库
- UI 显示调用轨迹：`调用 legal_statute · semantic · 420ms · N 条`
- 未命中提示「演示库未收录；缺源不编造」

### 7.2 生产接入

| 项 | 要求 |
| --- | --- |
| 法条 | `legal_statute`：semantic / search_article / article_detail |
| 案例 | `legal_case`：semantic / keyword / detail；权威库开关 |
| 引用 | 必须附返回 url；判项/原文引用前必须 detail 核对 |
| 时效 | 非现行有效必须标注 |
| 境外法 | 不在本期；不得表述为中国大陆现行法 |
| 失败 | 超时/异常 → 明确报错，不静默降级为编造 |

参数契约与 AutoClaw `legal_statute` / `legal_case` 保持一致，见工具 schema。

## 8. 页面与信息架构（v1.2）

### 8.1 首页

- 新建案件（核验 / 起草 + 立场/笔记）
- 我的案件 + 示例案件
- 待处理数直读红灯+待核验

### 8.2 工作台（三栏 + 助手）

```
┌ 顶栏：Logo | 当前案件▾ | 原告·被告｜法院 | 案件记忆(实心) ┐
├ 左：材料分组(统一折叠) | 关联法条L2 | 关联案例L3 ┤
├ 中上：文书N | 标签(核验徽标) | ✦AI助手 ┤
├ 中：当前文书头（文书名 | ✎在线编辑 | AI核验） ┤
├ 中：编辑条(编辑态) | 正文纸 ┤
├ 中下：AI 助手（精简能力条+对话+自适应输入，更多菜单向上弹）│
└ 右：核验待办（默认） / 本句核验 ┘
```

#### 文书标签核验徽标

不点进文书也能感知状态：

| 徽标 | 含义 |
| --- | --- |
| 红点 + 数字 | 该文书有 N 项不通过 / 待核验（阻断导出） |
| 黄点 | 仅预警，可选复核 |
| 绿点 | 核验项已处理 |
| 无徽标 | 尚未核验（无声明） |

#### 左栏关联依据与折叠

- L1 材料按原分组展示，点组名折叠 / 展开
- AI 关联、手动挂靠、MCP 引用的 L2 法条与 L3 案例，去重后归档到「关联依据 · AI / 手动」下的 法条 L2 / 案例 L3 两组
- 条目带 `手动` / `MCP` 角标；点击打开预览抽屉
- 当前案件选择器在标题栏，不再占左栏首屏

### 8.3 在线编辑器（新）

- 顶栏「✎ 在线编辑」或 `⌘/Ctrl+Shift+E` 进入
- 仅声明级 `<mark>` 可编辑（`contenteditable`），避免整篇重排
- 输入防抖 550ms 提交 `SET_EDIT`；该句转待核验，角标「待重核」
- 编辑条：局部重核（dirty 集）/ 全文重核 / 完成编辑
- 局部重核命中 `verifiedText` → 直接通过（演示 c1-q4 可改对日期金额后变绿）

### 8.4 核验待办（右栏默认）

- 进度条：已处理 / 总数 / 百分比
- Tab：待办（红+待核验+黄）/ 预警 / 标注 / 已通过
- 卡片：状态 + 类型 + 段位 + 一句话原因 + 原文摘要 + 建议改文
- 点击进本句核验卡

### 8.5 核验报告页（按律师习惯重组）

信息不再散铺，改为**结论 → 动作 → 分组待办 → 案例 → 留痕**：

1. 横幅结论：可导出 / 需修改后复检 / 禁止外发 + 核验时间 + 库版本
2. 下一步动作三卡：
   - ① 审阅版 Word（原生批注）
   - ② 清洁正文＋核验报告
   - ③ **案例检索报告**（一键导出本文书 L3 案例）
3. L1/L2/L3 分类计数
4. 折叠分组：一必须处理 / 二待核验 / 三建议复核 / 四通过标注
5. 联动影响
6. 案例检索报告预览 + 再次导出
7. 人工与助手操作记录（折叠）
8. 核验时间与库版本 + 律师责任声明

### 8.6 案例检索报告（新交付物）

Word 结构：

1. 检索任务（案件、文书、律师、时间、口径）
2. 结果概览（卷内联动 N 条 + MCP 补充 M 件）
3. 案例清单表（案号、名称、法院、效力/命中、文书状态）
4. 逐案摘录（四要素、要旨、文书原文对照）
5. 核验声明（官方库为准；演示环境说明；AI 仅辅助）

入口：报告页一键导出；本句核验卡（E-CASE）单案导出；助手 `case-report` skill。

### 8.7 案件记忆（按律师关注点重排）

六个视图：

| 视图 | 律师问题 |
| --- | --- |
| 办案速览 | 这案是什么？我代理谁？文书进度？ |
| 立场与焦点 | 我方目标？对方主张？争点？ |
| 事实时间线 | 什么时间发生了什么？有据吗？ |
| 证据地图 | 哪些声明有出处？哪些缺源？ |
| 金额台账 | 数字怎么来的？能复算吗？ |
| 风险与待办 | 会出事的地方？怎么补？ |

速览含：一句话案情、代理立场（可编辑，起草必读）、律师笔记、文书进度、关键人物。

每个关键卡都有「✦ 问 AI」直达助手。

## 12. 边界与免责

1. 核验使用演示资料、有限规则和人工复核
