# 官方法源与更新策略

## 结论

LawVerify 的法条原文库建议采用“1 个主法源 + 3 个官方补充源”的结构：

1. `国家法律法规数据库（flk.npc.gov.cn）`
   - 主体维护：全国人大常委会办公厅
   - 适用范围：宪法、法律、监察法规、司法解释、地方性法规，以及大量现行有效规范文本
   - 角色定位：系统主法源，优先用于法律条文点击预览、引用核验、法条正文展示

2. `国家行政法规库（xzfg.moj.gov.cn）`
   - 主体维护：司法部 / 中国政府网
   - 适用范围：行政法规
   - 角色定位：行政法规专项主源，适合做自动更新与版本追踪

3. `国家规章库（gov.cn）`
   - 主体维护：中国政府网
   - 适用范围：部门规章、地方政府规章
   - 角色定位：规章层补充源

4. `司法部规章库（moj.gov.cn）`
   - 主体维护：中华人民共和国司法部
   - 适用范围：司法部规章、司法行政规范性文件
   - 角色定位：司法行政专题补充源

## 为什么这么选

- 权威性最高：全部是国家机关官方站点，不依赖商业库或转载站
- 可持续更新：都具备持续维护机制，其中国家行政法规库明确声明“动态更新”
- 可核验：人大库与行政法规库都提供正式版本入口，行政法规库还提供文字版 / 图片版下载
- 适合法律工作流：右侧预览不仅能展示条文文本，还能保留“官方原文”入口，方便律师交叉核对

## 数据落库建议

`knowledgeStatutes` 中每部法律文件至少保留以下字段：

- `title`
- `docType`
- `issuer`
- `effectiveStatus`
- `effectiveDate`
- `publishDate`
- `revisionDate`
- `version`
- `sourceProvider`
- `sourceAuthority`
- `sourceUrl`
- `sourceTextUrl`
- `sourcePdfUrl`
- `sourceDocumentId`
- `sourceVerifiedAt`

条文级继续沿用当前结构：

- `articleNumber`
- `content`
- `plainText`
- `aliases`
- `topicTags`

## 更新策略

### 1. 日常更新

- 每日一次增量巡检
- 先巡检人大库、行政法规库
- 再巡检规章库和司法部规章库

### 2. 更新判定

命中以下任一条件即判定需要更新：

- 官方来源的发布日期 / 修订日期变化
- `sourceDocumentId` 变化
- 原文正文摘要哈希变化
- 当前库内 `sourceVerifiedAt` 超过设定阈值

### 3. 更新写入方式

- 若同名法律出现新修订版本，不覆盖旧版本快照
- 当前工作区默认指向“现行有效版本”
- 历史版本单独保留，供案件溯源和旧法比对

## 点击法条预览的落地方式

当文书中点击某条法条引用时：

1. 先根据 `reference.targetId` 找到本地 `knowledgeStatutes` 对应条文
2. 在右侧展示：
   - 法律标题
   - 条号
   - 条文原文
   - 版本信息
   - 官方来源
   - “官方原文”跳转入口
3. 若本地未命中，再走官方源检索与补库流程
