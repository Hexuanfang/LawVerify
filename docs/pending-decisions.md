## P-01 案件状态自动流转规则

- **背景**：案件状态目前有 `draft / in_review / ready` 三态，只能由用户在文书工作区手动点「标记已核验 / 恢复为核验中」切换。
- **现状**：`selectedCase.status` 不会随材料或文书变化自动变化；`canMarkCaseReady` 只在前端计算，用于禁用按钮。
- **影响**：材料更新后案件仍停留在「已核验」，归档语义失真；用户要自己记得回改状态。
- **需要确认**：
  1. 导入/删除材料后，案件是否自动回到 `draft`（筹备中）？
  2. 全部段落核验后，是**自动**改为 `ready`，还是只提示一次（建议：提示一次，由用户确认）？
  3. 状态回退是否需要留痕（谁在什么时候改的）？
- **建议**：采用「导入新证据自动回退到 `draft` + 核验完成后弹出一次确认提示但不自动落库」，并为状态变更补一条操作日志。
- **状态**：待确认

| 重复材料标记与跳过 | 同一文件被重复导入会重复消耗并可能触发失败 | 同一案件内内容哈希相同的材料保留最早一份，其余标记 `duplicateOf`；重复材料跳过理解、不进案件记忆，目录树文件后显示黄叹号（悬停显示重复对象），绿勾=理解完成、红叉=理解失败 |
| 自动理解并发化 | 自动理解一次只处理一份材料，整案理解耗时随材料数线性增长 | 材料理解拆成「解析原件 / 准备状态 / 模型理解 / 落库」四段，耗时的模型调用放在工作区写锁之外并发执行；自动梳理默认同时处理 3 份材料；工作区写入用账户级写锁串行合并，避免并发写回互相覆盖；扣费登记与模型理解分离，结算流程跳过执行中的扣费防止重复退款。并发上限由 `EVIDENCE_SUMMARY_CONCURRENCY` 与 `EVIDENCE_UNDERSTANDING_LLM_CONCURRENCY` 控制 |
| 本地服务被看门狗误杀 | 证据联动与自动理解期间必定失败，报「本地材料服务暂不可用 / 处理连接已中断 / 本地服务暂不可用，请重新打开 LawVerify」，控制台是 `ERR_CONNECTION_RESET` 与 `ERR_CONNECTION_REFUSED` | 根因是服务端每次读写工作区都重算证据匹配（几十份材料时单次 365ms），自动理解批量落库把事件循环连续占满数十秒，桌面端 20 秒 ping 超时后直接杀掉服务。修复：派生结果按内容指纹缓存复用（读操作提速约 10 倍，事件循环阻塞从 38.7 秒降到 0.6 秒）、SQLite 不再每次连接重设 `journal_mode`、前端工作区同步加 1.5 秒节流、后台队列兜底 catch、未捕获的 Promise 拒绝不再杀掉服务、看门狗超时放宽到 60 秒且失败后仍在后台低频重试 |
| 自动理解排队竞态 | 自动理解任务长期停在「正在梳理案件」，材料始终没有理解结果 | `GET /api/workspace` 的处理函数会把未完成的梳理重新排队，而排队会清掉并重设 1500 毫秒的调度定时器；前端在后台处理期间持续轮询，定时器被无限推迟，任务永远得不到执行。修复：排队改为幂等，已在队列中的任务不重置定时器。回归测试 `scripts/test-case-agent-queue-race.mjs` 覆盖「持续读取工作区时自动理解仍能完成」 |
| 法条引用的版本正确性 | 自动挂接法条不看版本状态，废止版本也会被当作依据；官方接口只返回法条元信息，占位说明被当成引文展示 | 引用按版本分级：废止版本带「不可直接引用」警示且不计入有效法条数，已修订版本标注适用时点待核对；占位说明不再作为引文，改为「条文正文待补」；同一部法律多个版本时现行有效优先。警示在引用卡片上单独呈现 |
| 超大材料理解的耗时 | 几百页 PDF 走「逐页渲染 + 逐页视觉」，渲染耗时数小时、视觉调用上万次，用户直接放弃 | 改为文本优先：有文本层的 PDF 直接按文本理解；扫描件视觉页数封顶（默认 10 页）并复用导入阶段已渲染的页图；视觉或汇总整体失败时降级为规则化记忆并写入风险，不再让整批材料中断 |
| 超大材料的覆盖率取舍 | 全文理解不可能在可接受时间内完成，检索式理解必然牺牲覆盖率 | 超过 500 页的材料改走检索式理解：按 300–800 字切块并建块级索引，检索命中块并带回前后相邻块，只把命中内容交给模型；覆盖情况写入材料记忆的风险。争议焦点在联动阶段明确后再做一次增量检索与理解，已覆盖块不重做 |
| 程序瑕疵的漏检 | 举证期限、形式要件、签章瑕疵不在争议焦点的语义空间里，检索式理解会整片漏掉 | 规则扫描独立于模型理解与检索链，按固定规则扫描并写入材料记忆，前端单独成组展示 |
| 增量上传后旧材料与联动结果过时 | 新证据进来后，旧的大材料只按通用争点词命中过，新证据里的具体事实（金额、日期、当事人）可能落在未覆盖的块里；已保存的文书联动也不会自动包含新证据 | 新证据理解完成后用其具体事实回头对超大材料做增量检索与理解，已覆盖的块不重做；文书联动记录材料指纹，材料增删或重新理解后工具栏提示「材料有更新，联动结果可能已过时」 |
