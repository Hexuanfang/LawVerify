# 严格 benchmark v2

本评测用于发现问题，不以满分为目标。保留旧 v1 基线，所有运行数据保存在项目内。

## 运行

从项目根目录执行：

```powershell
npm --prefix server run test:benchmark:metrics
npm --prefix server run typecheck:eval
npm --prefix server run test:benchmark:strict
```

严格离线模式因实际缺陷或模型未测返回 **1** 是有效评测结果，不表示程序崩溃。宽松模式 `npm --prefix server run test:benchmark` 仍在报告中保留“不通过”。

报告为 `server/eval/reports/v2/latest.md`、`latest.json`，同时保留时间戳版本。JSON 保存逐条失败、输入输出、文件/源码 SHA256、阈值与模式。运行数据位于项目 `tmp/benchmark-v2-*`；不操作真实工作区。若 npm shim 失效，可在 `server` 内用真实 Node 路径执行 `node --import tsx eval/v2/runner.mjs --strict`。

## 数据

- 8 个合成案件、128 条主张、64 份材料。覆盖买卖、借贷、工程、租赁、劳动、服务、保险与委托代理。八案共用边界模板，**不是八套独立采样的真实案件**。
- 显式标注支持、金额/日期/否定冲突、无证据、同名不同主体、补充协议、底稿 context、身份字段与多证据共同支持。标准答案不由被测函数生成，也不发送给模型；未经独立法律专家复核。
- 材料角色为已知评测设置，未衡量生产材料角色分类能力。
- 13 个真实附件：6 个正常 PDF、6 个 PNG、1 个故意损坏的 PDF。覆盖扫描、同页文图混合、文字/扫描交替、四页扫描、表格、聊天、90 度旋转、低对比度与模糊。扫描图片没有隐藏文字层。
- `media-manifest.json` 保存每页原文、金额/日期/主体/否定词等关键字段、主张及文件哈希。表格行与聊天顺序通过全文字符序列及复合字段核对；尚无版面坐标、印章真伪与表格结构单独指标。

生成附件使用环境已有 Python/Pillow/reportlab，不新增项目依赖：

```powershell
python server/eval/v2/build-media.py --font C:/Windows/Fonts/simhei.ttf
```

不同字体或库版本可能改变附件字节；应一并保留附件与匹配清单，运行时先核对哈希。

## 分层口径

1. **生产文件提取**：真实字节通过 `boundedFileStorage` 落盘，调用生产 `parseDocument` 与 Python workers，按解析 blocks 的实际页码核对关键字段、CER、页数。PDF 与图片均执行本地 MinerU 解析，可选视觉模型转录单独评分。
2. **生产检索组件**：调用生产 chunk 构建、索引与 BM25 排序，按材料去重计算 recall@1/@5；不等同于完整生产候选编排。无证据负样本不参与召回分母。
3. **生产挂接防线**：64 个注入探针核对虚构引文、身份误用、标题、底稿降级、真实引用错挂、相反语义与页码。固定输入结果不是模型实测准确率。
4. **严格解析契约**：10 条格式探针核对完整输出字段；畸形关联被错误接受计失败。生产解析器只做信封恢复时，也会暴露不满足严格契约的结果。
5. **评分器自检**：9 类变异必须降分，包括漏挂、错材料/关系/页码、伪造引文、重复、禁挂句错挂、删除否定词。此项满分仅表示能检出这些故障。
6. **真实模型与文件链路**：默认未测；不能从组件分数推断。空分母显示 N/A，缺少模型与视觉结果时完整验收失败。

生产私有函数沿用项目测试的 TypeScript AST 加载方法，避免启动账户、数据库和后台案件任务。存储来源及 ID/富文本等外围依赖注入；解析、分片、挂接和定位执行原函数。源码函数缺失时直接报错，报告保存指纹。不覆盖 HTTP 路由、权限、生产完整 overview/候选编排/缓存。

## 可选真实模型

```powershell
# 实际调用模型，会产生供应商费用
npm --prefix server run test:benchmark:live
```

使用项目已有 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL`，视觉可配置 `LLM_VISION_*`。强制直连，不调用云端账户积分网关。凭据不写入数据或报告。

文本模型使用 benchmark 独立核验 prompt，再交给生产挂接防线；视觉使用每页真实图像转录。**这是 benchmark 视觉适配器 + 生产挂接，不是生产完整模型/OCR 编排的端到端测试。** 文件链路只向模型提供实际解析/视觉输出，评分时才使用独立原文答案。分别展示原始模型提案和生产过滤后结果，避免过滤错误造成模型满分。

`--live` 不带 `--vision` 仍是部分验证。超时、缺段、重复/未知 ID、格式错误和未测均不能静默算通过。

严格目标：关键字段/页码 100%，CER ≤2%，防线/解析/评分器自检 100%，组件 recall@5 ≥95%，模型 Precision ≥95%、Recall ≥90%、关系 ≥95%，禁挂负样本全部正确。这些是工程目标，不是业务准确率保证。
