# v1.2 核验评测基线（T0）

本目录按实施计划 §3 的建议口径冻结工程基线，不代表律师已作金标确认，也不作为应用运行时的输入。进一步会签见实施计划 T10。

## 独立标注与结论置信度

置信度估计同组 AI 自动结论与律师独立复核一致的概率。按声明类型、自动结论、原文是否可定位、来源类型和检查项是否仍有待定问题分组。已完成原文比对且检查全部通过、仅待律师确认的声明按「支持」处理。证据比对尚未完成的声明暂不给概率。

在 `server` 目录运行以下命令。输入为经授权导出的 `/api/workspace` JSON 响应或其中的 `workspace` 对象，请只使用面向此评测的脱敏案件。导出前，在同一模型、核验规则版本及来源配置下完成核验。

```powershell
node --import tsx eval/verification/calibrate-confidence.mjs prepare ../tmp/workspace.json ../tmp/lawyer-review
```

将 `annotations.json` 交给律师。该文件包含原文片段和回查位置。独立复核时应查阅该版本的原文和卷宗，只填写 `reviewer`、`reviewedAt`（`YYYY-MM-DD`）以及每条声明的 `verdict`，保留 ID。`predictions.json` 由评测人员单独保存，其中包含 AI 结论及分组。

| 标注值 | 律师复核结论 |
| --- | --- |
| `pass` | 有出处支撑声明，关键比对一致 |
| `warn` | 存在需要提示的疑点、适用限制或部分支持 |
| `fail` | 有依据确认声明不通过 |
| `miss` | 缺少结论所需的出处 |
| `pending` | 当前仍无法完成判定 |
| `null` | 本条尚未复核 |

```powershell
node --import tsx eval/verification/calibrate-confidence.mjs fit ../tmp/lawyer-review/predictions.json ../tmp/lawyer-review/annotations.json ../tmp/verification-calibration.json
```

案件按稳定 ID 划入校准集或验证集。每组每案预先抽一条代表声明，未标注的代表不计入。每组两边各需至少 40 个独立案件，留出一致率与估计概率的差值最多 10 个百分点，且留出集的 95% Wilson 区间必须落在估计概率上下 20 个百分点内。门槛按组检查，稀缺分组会继续显示「暂无校准数据」。通过验证后，校准文件只包含分组统计和版本信息。验证集应一次性留出，调整分组或换模型后使用新的独立验证样本。

部署时将 `VERIFICATION_CALIBRATION_FILE` 指向通过验证的 JSON 文件的绝对路径。该文件只用于对应的模型和核验规则版本。重新核验后，核验卡显示概率、判断依据、校准与验证案件数、验证一致率和校准版本。无文件、文件无效、规则版本不符或分组未达标时，展示「暂无校准数据」。

## 真值与溯源

| 文件 | 内容 | 使用边界 |
| --- | --- | --- |
| `fixtures/seed/documents.json` | 从 `cases.js` 逐案逐文书按原型顺序还原的正文片段：c1 十份、c2 一份 | 每个原型正文片段占一个合成段落；不是完整 Word，不用来验收版式、页码或证据清单真实坐标 |
| `fixtures/seed/sources.json` | 随案材料目录和原型记录的 L1、L2、L3 摘录 | `S…` 仅在同案内有效；原型摘录可能含总结、缩略、省略号或替代条文提示。不得把摘录当权威全文或 L3 判项原文 |
| `fixtures/seed/supplements.json` | 按原型语义构造、明确标注的受控前审材料与废止效力记录 | 只用于离线局部规则。无可靠旧条文正文时保持空值，不以替代条文回填 |
| `fixtures/seed/expected.json` | 36 条原始记录：c1 32 条、c2 4 条，保留原始 verdict、已有检查、原标注理由、依赖和来源比对 | `paragraphIndex` 从 0 开始；匹配标签只在真值侧。缺失检查不等于已通过。不要把 `verifiedText`、补证建议或源比对标签交给生产核验 |
| `fixtures/seed/provenance.json` | 冻结版本、相对源码路径和将 CRLF 归一为 LF 后的 SHA-256 | 用于追溯，避免因 Git 换行策略不同而误判漂移 |
| `fixtures/controlled.json` | ADV-01–12 和独立回归，`input` 与 `expected` 分开 | 离线 provider 响应、示例案号和 `example.invalid` 为受控数据，不访问网络；权威回查和生产契约另验 |
| `fixtures/case-details.json` | T5 受控裁判详情、判项及比对语境 | 合成裁判与合成来源，种子测试只复用冻结正文中的引用和案号 |
| `fixtures/extra/documents.json`、`fixtures/extra/materials.json` | 三个合成案件的 30 份正文、案由、我方立场及卷内材料 | `bench --set extra` 输出逐份清单、覆盖和输入哈希。对方执笔的正文沿用所在案件的我方立场，标题注明「对方文书」。清单按纯文本评测，表格行列另用真实 DOCX 夹具。律师金标待核定 |

按用途计分：`c1-z4` 是材料侧反向漏登诊断，原标注仍为 `warn`，但不合成正文且不计抽取召回；`c1-zs`、`c1-lsh`、`c1-flyj`、`c1-cx` 只检查对应元素和 `pending`。保留 `c1-l3` 原始 `pass`、`c1-s4` 原始 E-CLAIM。级联和混合句拆分用 `CASCADE-LAW`、`CASCADE-FACT`、`EXTRACT-MIXED-APPEAL` 独立测试。`cx` 是原型键，匹配 profile 时映射为 `proc`，不改写原始文档真值。

T2 离线评分暂按 §3.5 建议：先精确片段，再在同段比较包含关系或去空白后不超过较长片段 20% 的编辑距离；重复片段按段落、字符范围和表格坐标消歧。类型错不计抽取 TP。必拆召回只数已标有内容的实例，不用 `minExpect` 当分母。不拆误报率以参与完整抽取计分的每份文书 × 该 profile 的每个 off 类型为一次机会，多次误抽只记一次该机会，但每条仍计精确率误报。定位准确率核对段落、字符或已标明的表格坐标；无法从冻结原文唯一回填位置的标签另列，不冒充定位通过。反向漏登与待核验占位不参与完整文书抽取得分。

重复表格原文共享段落和字符起点时，配对还须符合真值已标的行列位置。错单元格的预测保留为多抽，对应的未配对金标记漏检。

## ADV 与红线对应

| 用例 | 红线或规则 | 必须区分的断言 |
| --- | --- | --- |
| ADV-01 / 02 | R1；02 亦覆盖 R7 | 权威详情确认查无才判 B1/C1 `fail`；不补相似案号、其他条文或原文 |
| ADV-03 | R6 | 固定查到已废止旧法且不适用于事实时点；替代条文仅为建议 |
| ADV-04 | R3 | 法条比对只忽略空白和中英文逗号。格式容差、正确拦截均计 0。用 `R3-ACCEPTED-QUOTE`、`R3-PERIOD-EXPORTED` 分别验证错误接受及错误外发的判分 |
| ADV-05 / 06 / 07 | 对抗规则 | 缺证、证明目的越界、无锚指错分别判断；不是自动计入红线 |
| ADV-08 | R4 | 原审判项反转输出不得被接受；原始对抗文本本身不记为系统违规 |
| ADV-09 | A5 | 独立断言正文自相矛盾，不能以两句都有来源为由判通过 |
| ADV-10 | R10 | 超时不产生 L2 或引用；另测空回应、搜索零候选、403 |
| ADV-11 / 12 | R9 / R5 | AI 写入即待核，即使已匹配材料；逐一对 `fail`、`miss`、`pending` 断言两种 Word 都无文件产出 |
| `SOURCE-ABSENT` / `SOURCE-NO-URL` | R2 | 无有效来源不贴 L1/L2/L3；无 URL 且无本地回查入口不是已核引用 |
| `SOURCE-SAME-NAME-WRONG-PERIOD` / `STATUTE-REPLACEMENT-ONLY` | R7 | 同名异期材料、替代条文均不得补位 |
| `CASE-SUMMARY-NOT-OPERATIVE-TEXT` / `CASE-NO-BODY` | R8 | 摘要和空详情均不得作为判项原文 |

`bench --set all` 在 `seed.caseChecks` 展示 `c1-q7` 和 `c1-l3` 的 C1–C7、四要素和命中分层。受控比对语境及裁判详情与冻结真值独立。两条级联从生产判定器取得依赖关系，再单独改变上游状态。`adversarial.caseMetrics` 记录受控四要素、命中层级分布和取得详情后才允许引用的判项样本数。

## 状态转移与兼容

下表是后续实现和验收口径，不是已上线行为。

| 输入或变化 | 目标状态与导出 | 兼容与留痕 |
| --- | --- | --- |
| 新导入、AI 内容采纳、修改正文、依据版本过期 | `pending`，阻断两种文书 Word | 保存原文、AI 标记及审计；受影响依赖重新计算；草稿保存失败不使用旧版本导出 |
| 权威详情确认当前引用不存在，或发现冲突、失真、失效 | `fail`，阻断 | 错误的声称仍可展示用于定位，不视为已核引用；人工勾选不能直接放行 |
| 按适用规则确认缺有效来源 | `miss`，阻断 | 不展示为已联动；失效历史引用可保留在审计，不算有效来源 |
| 超时、空响应、403、仅有模糊检索零候选 | `pending`，阻断 | 记录错误类型，可重试；不得伪造引用或等同权威查无 |
| 当前快照的规则核验无阻断，仅有已判定预警 | `warn`，不阻断 | 预警保留在报告，待办与导出门禁分开计算 |
| 核验通过，或通过且人工留注 | `pass` / `note`，不阻断 | 旧 `verified`、笔记、手工来源和历史审阅兼容读取；历史确认不替代当前版本核验 |
| 上游事实变 `pending`，或上游法条失效 | 受影响下游按 C4 / C6 局部重开并可降为 `warn` | 原始离线真值不覆盖；文书整体仍按上游阻断项计算 |
| 旧稿只有 `paragraph.link`、没有结构化核验结果，或版本无法对应 | 首次导出前重核；否则按 `pending` 阻断 | 兼容读旧关联，不覆盖旧记录；提供重核入口。存储和 API 扩展另评审 |
| 独立案例检索报告 | 不继承两种正文 Word 闸门 | 只输出可回查字段并显示核验状态，不把候选当作文书已关联引用 |

在仓库根目录执行：

```powershell
node --test server/eval/verification/seed.test.mjs
node server/eval/verification/freeze-seed.mjs --check
```

只有明确接受源数据变更时，才移除 `--check` 重新生成四个受原型追踪的快照；受控补充材料不随生成器覆盖。测试检查 fixture 结构、覆盖和溯源，不运行生产抽取、核验、导出或真实检索。
